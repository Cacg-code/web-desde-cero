Pedir bien: prompts que funcionan al programar

  • ⏱ 50 minutos
  • 📶 Nivel: básico
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Escribir prompts con contexto, tarea, restricciones y formato esperado.
  • Pedir un plan antes del código y dividir tareas grandes en pasos pequeños.
  • Iterar con correcciones concretas en vez de empezar de cero.

La calidad de la respuesta depende, sobre todo, de la calidad de lo que pides. Un buen prompt para programar se parece mucho a una buena descripción de tarea para un compañero que acaba de llegar al proyecto: no conoce nada, así que tienes que contarle lo importante.

1.La fórmula: contexto, tarea, restricciones, formato

ParteQué incluyesEjemplo
ContextoTecnología, versión, qué hay hecho"Proyecto con Node 24 y Express 5, sin TypeScript."
TareaUna cosa concreta"Agrega una ruta DELETE /tareas/:id."
RestriccionesQué sí y qué no"Sin librerías nuevas. Mantén el estilo de rutas/tareas.js."
FormatoCómo quieres la respuesta"Muéstrame solo el cambio y una frase explicando."

Compara estos dos pedidos:

texto
❌  "hazme un login"

✅  "Estoy en un proyecto Express 5 con SQLite (better-sqlite3).
    Tarea: agrega POST /login que reciba email y password en JSON.
    Restricciones: guarda contraseñas con bcrypt, responde 401 si fallan,
    no uses librerías de sesión todavía, sigue el estilo de rutas/tareas.js.
    Formato: primero un plan de 3-5 pasos; no escribas código hasta que yo diga 'sigue'."

2.Pide un plan antes del código

Cuando la tarea toca varios archivos, pide primero un plan: qué archivos cambiará y en qué orden. Revisarlo toma un minuto y evita 20 minutos de código en la dirección equivocada. Muchos editores y agentes tienen un "modo plan" justo para esto.

💡 Consejo

Frase útil: "Antes de escribir código, dime qué dudas tienes y qué archivos tocarías." Obliga a la IA a mostrar sus suposiciones.

3.Da ejemplos y muestra lo que existe

  • Pega el error completo (no tu resumen) y el trozo de código involucrado.
  • Si quieres un formato, da un ejemplo de entrada y salida: "con [1,2,3] debe devolver 6".
  • En un editor con IA, adjunta los archivos relevantes (en Cursor se mencionan con @archivo) en lugar de describirlos de memoria.
  • Si usas una librería reciente, pega el enlace o el fragmento de su documentación: así no depende de lo que recuerde.

4.Itera con correcciones concretas

Si el resultado no sirve, no digas "está mal". Di qué está mal:

  • "Usaste var; en este proyecto usamos const y let."
  • "Esta función hace dos cosas; sepárala en dos."
  • "Falla cuando la lista está vacía. Agrega ese caso."

Si la conversación se enreda, abre una nueva con un resumen corto de lo decidido. Los chats muy largos pierden precisión y cuestan más.

5.Una tarea, un cambio, un commit

Pide cosas pequeñas y verificables. Después de cada una que funcione: pruébala y haz git commit. Así, si el siguiente pedido rompe algo, sabes exactamente dónde volver.

📒 Apuntes para llevar

  • Un buen prompt tiene contexto, tarea, restricciones y formato.
  • Para cambios grandes, pide un plan primero y apruébalo.
  • Pega el error completo y adjunta los archivos reales; no describas de memoria.
  • Corrige con detalles concretos; si el chat se enreda, empieza uno nuevo con un resumen.
  • Una tarea pequeña por vez y un commit por cada una que funcione.

6.Glosario

TérminoSignificado
PromptEl mensaje o instrucción que le das a la IA.
Modo planFunción donde la IA propone pasos sin modificar archivos hasta que apruebes.
RestricciónLímite que impones: librerías permitidas, estilo, qué no tocar.
IterarMejorar el resultado con correcciones sucesivas.

🧠 Comprueba lo aprendido

Elige una respuesta en cada pregunta. Verás al instante si acertaste y por qué.

¿Cuál es un prompt mejor?

Da contexto, el error real, el archivo y el resultado esperado.

¿Para qué sirve pedir un plan antes del código?

Corregir un plan es más barato que corregir código ya escrito.

Si una conversación larga se enreda, lo mejor es…

Un contexto limpio da respuestas más precisas.

¿Qué hacer después de que un cambio pedido funciona?

Los commits pequeños permiten volver atrás con precisión.
