IA dentro de tu app: llamar a un modelo desde Node

  • ⏱ 60 minutos
  • 📶 Nivel: avanzado
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Llamar a la API de un modelo desde Node sin exponer la clave.
  • Pedir una respuesta en JSON y validarla antes de usarla.
  • Controlar costos, límites y fallos con un diseño de "reglas primero, IA después".

Hasta ahora usaste la IA para programar. Ahora la vas a poner dentro de lo que programas: clasificar mensajes, resumir textos, extraer datos de un pedido escrito libremente. El patrón es siempre el mismo: tu servidor habla con el modelo, nunca el navegador.

1.Regla 1: la clave vive en el servidor

Si pones la clave de la API en el JavaScript del navegador, cualquiera puede verla en las herramientas de desarrollo y usarla a tu costa. La clave va en una variable de entorno de tu servidor (Node, un Cloudflare Worker, etc.) y el front llama a tu ruta:

texto
Navegador  →  POST /api/clasificar (tu servidor, con límite y validación)
                      →  API del modelo (con la clave secreta)

2.Una llamada mínima desde Node

Muchos proveedores aceptan un formato de "chat" muy parecido. Para que el código no dependa de uno solo, guarda URL, clave y modelo en variables de entorno (consulta en la documentación de tu proveedor los valores y los nombres vigentes):

javascript
// ia.js  (Node 24: fetch ya viene incluido)
const { IA_URL, IA_KEY, IA_MODELO } = process.env;

export async function preguntar(mensajes, { maxTokens = 300 } = {}) {
  const r = await fetch(IA_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${IA_KEY}` },
    body: JSON.stringify({ model: IA_MODELO, messages: mensajes, max_tokens: maxTokens }),
    signal: AbortSignal.timeout(15_000),   // no esperes para siempre
  });
  if (!r.ok) throw new Error(`IA respondió ${r.status}`);
  const datos = await r.json();
  return datos.choices[0].message.content;   // el formato exacto depende del proveedor
}
bash
node --env-file=.env servidor.js

💡 Consejo

Cada proveedor tiene su propio formato de respuesta. Lee su guía oficial, o usa su paquete (SDK) oficial de JavaScript si prefieres no armar el fetch a mano.

3.Respuestas en JSON: pide, valida y no confíes

Para usar la respuesta en tu programa necesitas datos, no prosa. Pide un formato fijo y valídalo siempre: el modelo puede devolver texto extra o un campo inventado. Varios proveedores ofrecen "salida estructurada" con un esquema; si la tienes, úsala y valida igualmente.

javascript
const CATEGORIAS = ['pedido', 'consulta', 'reclamo', 'otro'];

export async function clasificar(texto) {
  const salida = await preguntar([
    { role: 'system', content: 'Clasifica el mensaje. Responde SOLO JSON: {"categoria": "pedido|consulta|reclamo|otro"}' },
    { role: 'user', content: texto.slice(0, 500) },      // limita lo que envías
  ]);
  try {
    const { categoria } = JSON.parse(salida);
    return CATEGORIAS.includes(categoria) ? categoria : 'otro';
  } catch {
    return 'otro';                                       // plan B si el JSON viene roto
  }
}

4.Reglas primero, IA después

La IA cuesta, tarda y a veces falla. Diseña así: 1) reglas simples (palabras clave, botones, expresiones regulares) resuelven lo común; 2) solo lo que no encaja pasa al modelo; 3) si el modelo falla o tarda, hay una respuesta de reserva. Es la misma arquitectura de la lección 22 del curso de chatbots.

5.Costos, límites y privacidad

  • Se paga por uso (tokens de entrada y salida). Limita el largo de lo que envías (slice) y de lo que recibes (max_tokens).
  • Límite por usuario en tu ruta, para que nadie vacíe tu saldo con un script.
  • Presupuesto y alertas en el panel del proveedor.
  • Cachea respuestas a preguntas repetidas.
  • Privacidad: no envíes datos personales de más; avisa al usuario cuando hable con una IA y ofrece una persona de respaldo.
  • Nunca dejes que el modelo invente precios, plazos o políticas: esos datos salen de tu base de datos o de un archivo tuyo.

📌 Nota · Opciones de infraestructura

Si ya usas Cloudflare Workers (como en el curso de chatbots), puedes llamar a modelos desde el propio Worker con Workers AI y pasar el tráfico por AI Gateway para ver costos, límites y registros. Revisa los planes y límites vigentes en la documentación oficial antes de depender de ellos.

6.Ejemplo guiado: llamar a un modelo desde el servidor

Regla central: la clave del proveedor vive en el servidor, nunca en el navegador. Esquema mínimo con Express:

js
app.post("/api/resumir", limitarPeticiones, async (req, res) => {
  const texto = String(req.body.texto ?? "").slice(0, 4000);   // límite de entrada
  if (!texto.trim()) return res.status(400).json({ error: "Falta el texto" });
  try {
    const r = await fetch(process.env.URL_DEL_MODELO, {        // la URL y la clave vienen de variables de entorno
      method: "POST",
      headers: { "Content-Type": "application/json", Authorization: `Bearer ${process.env.CLAVE_IA}` },
      body: JSON.stringify({ /* cuerpo según la documentación de tu proveedor */ }),
      signal: AbortSignal.timeout(15000),                      // no esperes para siempre
    });
    if (!r.ok) throw new Error("Proveedor respondió " + r.status);
    res.json({ resumen: (await r.json()) /* extrae el texto según tu proveedor */ });
  } catch {
    res.status(502).json({ error: "El resumen no está disponible ahora. Intenta de nuevo." });
  }
});

Fíjate en lo que rodea a la llamada: límite de entrada, limitación de peticiones, tiempo máximo, error amable y clave en variables de entorno. La llamada al modelo es lo más fácil; lo demás es lo que evita facturas y abusos.

7.Errores frecuentes

  • Poner la clave en el código del front (aunque sea «solo para probar»): cualquiera la ve en DevTools y la usa a tu costa.
  • No limitar peticiones ni tamaño: un solo usuario (o un script) puede gastar tu cuota del mes en minutos.
  • Mostrar la respuesta del modelo como HTML sin sanearla: puede traer etiquetas o enlaces maliciosos.
  • Asumir que la salida sigue tu formato: si esperas JSON, valida la estructura y ten un plan si viene mal.
  • Enviar datos personales al modelo sin necesidad ni aviso al usuario.

📒 Apuntes para llevar

  • La clave de la API solo en el servidor; el navegador llama a tu ruta.
  • Guarda URL, clave y modelo en variables de entorno y usa timeout.
  • Pide JSON, valídalo y ten plan B si falla.
  • Arquitectura: reglas primero, IA para lo que no encaja, respuesta de reserva.
  • Controla costos: límites de entrada/salida, límite por usuario, presupuesto y caché.
  • Datos como precios y políticas salen de tu fuente de verdad, nunca del modelo.

8.Glosario

TérminoSignificado

Salida estructuradaRespuesta que cumple un formato o esquema (por ejemplo, JSON).
TimeoutTiempo máximo de espera antes de abortar una llamada.
