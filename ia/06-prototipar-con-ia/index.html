Prototipar con IA y pasar el código a tu proyecto

  • ⏱ 40 minutos
  • 📶 Nivel: básico
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Elegir cuándo conviene un prototipo generado y cuándo no.
  • Describir una interfaz para obtener un buen prototipo.
  • Pasar el código a tu repositorio, limpiarlo y entenderlo antes de usarlo.

Los constructores de apps con IA (v0, Lovable, Bolt, Replit y similares) convierten una descripción en una interfaz o app funcionando en minutos. Son perfectos para ver una idea antes de invertir horas o para enseñarle algo a un cliente. No son una forma de evitar entender lo que construyes.

1.Cuándo sí y cuándo no

Sí convieneNo conviene (todavía)
Probar rápido 3 ideas de diseño.Sistemas con pagos, datos sensibles o reglas de negocio complejas.
Maqueta para mostrar al cliente antes de cotizar.Entregar el resultado directo, sin revisar, como trabajo final.
Generar un componente base para pulir tú.Aprender: te saltas justo lo que necesitas practicar.

2.Cómo describir lo que quieres

Aplica lo del prompt: contexto, tarea, restricciones. Para interfaces, agrega estructura, estilo y estados:

texto
Landing para una barbería en Huaral.
Secciones: hero con botón "Reservar", servicios con precios de ejemplo, galería, mapa, WhatsApp flotante.
Estilo: oscuro, acentos dorados, tipografía grande, móvil primero.
Estados: botón con foco visible, textos con buen contraste, imágenes con alt.
Tecnología: React + Vite + CSS simple (sin librerías de componentes).

💡 Consejo

Pide cosas que ya conoces del curso (accesibilidad, móvil primero, HTML semántico). Si no las pides, muchas veces no vienen.

3.Del prototipo a tu código

  1. Exporta o conecta con GitHub (la mayoría lo permite) y clónalo en tu máquina.
  2. Ejecútalo: npm install (tras verificar dependencias), npm run dev.
  3. Léelo: estructura de carpetas, componentes, qué librerías usó. Elimina lo que no necesitas.
  4. Audítalo: accesibilidad (¿teclado? ¿contraste?), rendimiento (imágenes pesadas), SEO básico, claves o textos de ejemplo olvidados.
  5. Hazlo tuyo: renombra, ordena y añade AGENTS.md y pruebas. Desde aquí lo mantienes tú.

Muchas plataformas conectan base de datos o autenticación con un clic. Es cómodo, pero revisa de quién es la cuenta, dónde viven los datos del cliente y cuánto cuesta cuando el proyecto crece. Si trabajas para un cliente, eso debe estar a nombre del cliente.

📌 Nota · Licencias y honestidad

Si entregas algo a un cliente, di que usaste herramientas de IA para acelerar el trabajo y que tú lo revisaste y lo mantienes. Es honesto y profesional; lo que se cobra es tu criterio y tu responsabilidad.

📒 Apuntes para llevar

  • Los constructores sirven para prototipar y mostrar, no para entregar sin revisar.
  • Describe estructura, estilo, estados y tecnología; pide accesibilidad y móvil primero.
  • Pasa el código a tu repo, léelo, audítalo y límpialo antes de usarlo.
  • Datos y cuentas de un cliente deben estar a su nombre.
  • Sé transparente con el cliente sobre el uso de IA y asume la responsabilidad del resultado.

4.Glosario

TérminoSignificado
PrototipoVersión rápida para probar una idea, no el producto final.
AuditarRevisar de forma sistemática calidad, seguridad y accesibilidad.
Móvil primeroDiseñar primero para pantallas pequeñas y luego ampliar.
