El panorama: qué herramientas de IA existen para programar

  • ⏱ 45 minutos
  • 📶 Nivel: básico
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Explicar en pocas palabras cómo "piensa" un modelo de lenguaje y por qué se equivoca.
  • Distinguir los 4 tipos de herramienta: chat, editor con IA, agente de terminal y constructor de apps.
  • Elegir una herramienta según la tarea y montar tu entorno de práctica.

Programar con IA no es "pedirle a un robot que haga tu tarea". Es trabajar con un ayudante muy rápido que no entiende tu proyecto, a veces inventa cosas y nunca se cansa. Quien sabe programar lo aprovecha el doble; quien no sabe, no puede notar cuándo se equivoca. Por eso este nivel va después de HTML, CSS, JavaScript, React, Node y SQL.

1.Cómo funciona un modelo de lenguaje (lo mínimo que debes saber)

Un modelo de lenguaje grande (LLM) fue entrenado con enormes cantidades de texto y código. Cuando le escribes, calcula qué texto es más probable que siga. No ejecuta tu código, no "sabe" si algo funciona: predice algo que se parece a una buena respuesta. De ahí salen sus tres límites:

  • Alucinaciones: puede inventar funciones, opciones o paquetes que no existen y decirlo con total seguridad.
  • Conocimiento con fecha: sabe lo que había hasta su entrenamiento. Las versiones nuevas de una librería pueden no estar en su memoria.
  • Contexto limitado: solo "ve" lo que cabe en la conversación o lo que la herramienta le muestra de tu proyecto.

💡 Consejo

Regla de oro de este nivel: la IA propone, tú decides. Todo lo que entra a tu proyecto lo entiendes, lo pruebas y lo puedes explicar.

2.Los 4 tipos de herramienta

TipoEjemplos (2026)Sirve para
ChatChatGPT, Claude, GeminiPreguntar, entender un error, comparar opciones, planificar. No toca tus archivos: tú copias y pegas.
Editor con IACursor, GitHub Copilot (en VS Code), WindsurfAutocompletar mientras escribes, chatear sobre tu código abierto y pedir cambios en varios archivos con un diff que tú aceptas o rechazas.
Agente de terminalClaude Code, Codex, Gemini CLIRecibe una tarea ("agrega validación al formulario"), lee tu proyecto, edita archivos, ejecuta comandos y pruebas, y te muestra qué hizo.
Constructor de appsv0, Lovable, Bolt, ReplitGeneran una app o interfaz completa desde una descripción. Ideal para prototipos; el código final conviene revisarlo y hacerlo tuyo.

📌 Nota · Esto cambia rápido

Los nombres, planes y precios se mueven cada pocos meses. Lo que dura son los conceptos (contexto, revisión, pruebas, permisos). Antes de pagar algo, revisa la página oficial; casi todas tienen plan gratuito o de prueba limitado.

3.Cuál usar según la tarea

  • "No entiendo este error / concepto" → chat.
  • "Escribo una función y quiero que me ayude" → editor con IA (autocompletado + chat).
  • "Tarea con varios pasos en varios archivos" → editor en modo agente o agente de terminal, con tu repositorio en Git para poder deshacer.
  • "Quiero ver una idea funcionando hoy" → constructor de apps y luego pasas el código a tu proyecto.

Empieza con una sola herramienta: el editor Cursor que ya recomendamos en el curso sirve para chat, autocompletado y agente. Aprender una a fondo vale más que probar diez.

4.Prepara tu entorno de práctica

  1. Crea (o reutiliza) un proyecto pequeño con Git: la IA va a hacer cambios y necesitas poder volver atrás con git restore o git reset.
  2. Haz un commit antes de cada sesión con IA.
  3. Revisa que tu .gitignore incluya .env y node_modules: nunca debe subirse un secreto.
  4. Abre el proyecto en tu editor y activa el chat de la IA.
bash
git status            # que esté limpio
git switch -c practica-ia   # rama de prueba: si sale mal, la borras

5.Ejemplo guiado: la misma tarea con dos herramientas

Tarea: «mi formulario deja enviar el correo vacío». Mira cómo cambia el trabajo según la herramienta:

  • Chat: pegas el HTML del formulario y la queja. Te explica la causa (falta required o la validación) y te da un fragmento. Tú lo copias, lo pruebas y decides.
  • Editor con IA: seleccionas el formulario y pides el cambio. Ves un diff con líneas verdes y rojas; aceptas, rechazas o pides ajustes.
  • Agente de terminal: le dices la tarea; lee los archivos, edita, ejecuta tus pruebas y te resume. Tú revisas con git diff.

Para esta tarea pequeña basta el chat o el editor. El agente se justifica cuando el cambio toca varios archivos. Usar la herramienta más grande para todo es lento y más difícil de revisar.

6.Errores frecuentes

  • Creer que «lo ejecutó, entonces funciona»: un chat no ejecuta nada y un agente puede ejecutar mal. La prueba la haces tú.
  • Empezar sin Git: si el agente rompe algo y no hay commit previo, no tienes cómo volver.
  • Coleccionar herramientas: cambiar cada semana de editor te quita más tiempo del que ahorra. Elige una y úsala un mes.
  • Pegar secretos en el chat (claves, .env, datos de clientes): lo que pegas sale de tu computadora.

📒 Apuntes para llevar

  • Un LLM predice texto probable; no ejecuta ni comprueba tu código.
  • Sus tres límites: alucina, tiene fecha de corte y ve poco contexto.
  • Hay 4 tipos de herramienta: chat, editor con IA, agente de terminal y constructor de apps.
  • Trabaja siempre con Git y una rama de prueba para poder deshacer.
  • Aprende una herramienta bien antes de coleccionar muchas.

7.Glosario

TérminoSignificado
LLMModelo de lenguaje grande: programa que genera texto (y código) prediciendo lo más probable.
AlucinaciónRespuesta inventada que suena correcta.
ContextoTodo lo que el modelo puede "ver" en ese momento: tu mensaje, archivos adjuntos, historial.
AgenteIA que no solo responde: usa herramientas (leer archivos, ejecutar comandos) para cumplir una tarea.
DiffVista de cambios que muestra líneas añadidas y quitadas antes de aceptarlas.

🧠 Comprueba lo aprendido

Elige una respuesta en cada pregunta. Verás al instante si acertaste y por qué.

¿Por qué un modelo puede inventar una función que no existe?

Genera lo que "suena" bien; no verifica contra la documentación ni ejecuta el código.

¿Qué herramienta es la más adecuada para entender un error que no conoces?

El chat sirve para explicar y comparar sin tocar tus archivos.

¿Qué debes hacer antes de dejar que un agente edite tu proyecto?

Con Git puedes revertir cualquier cambio malo.

¿Qué dura más tiempo que los nombres de las herramientas?

Las herramientas cambian; el método de trabajo se mantiene.
