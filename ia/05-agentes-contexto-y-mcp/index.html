Agentes, AGENTS.md y MCP: trabajar con IA que actúa

  • ⏱ 55 minutos
  • 📶 Nivel: intermedio
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Escribir un archivo AGENTS.md con las reglas de tu proyecto.
  • Controlar permisos y trabajar con el ciclo plan → cambio → prueba → commit.
  • Explicar qué es MCP y cuándo conviene (y cuándo no) conectarlo.

Un agente no solo responde: lee archivos, edita, ejecuta comandos y repite hasta cumplir la tarea. Eso lo hace muy útil y también más riesgoso, así que necesita contexto claro y límites claros.

1.El ciclo de trabajo con un agente

  1. Rama o commit limpio antes de empezar.
  2. Plan: pídele que lo describa y apruébalo.
  3. Un cambio pequeño a la vez.
  4. Verificación: que ejecute las pruebas y el linter; léelos tú.
  5. Revisión del diff y git commit.

2.AGENTS.md: el manual de tu proyecto para la IA

Cada vez que abres una conversación nueva, el agente empieza sin saber nada de ti. AGENTS.md es un archivo en la raíz del repositorio con las instrucciones que quieres que lea siempre: cómo instalar, cómo probar, el estilo de código y qué no tocar. Es un formato abierto que usan varias herramientas (Codex, Cursor, entre otras); algunas tienen su propio nombre además (por ejemplo, Claude Code lee CLAUDE.md y Gemini CLI GEMINI.md). Si usas varias, puedes mantener un único contenido y que los demás archivos apunten a él: revisa la documentación de la tuya.

markdown
# AGENTS.md

## Proyecto
API de tareas con Node 24 + Express 5 + SQLite. Front en React + Vite.

## Comandos
- Instalar: `npm ci`
- Pruebas: `node --test`
- Desarrollo: `npm run dev`

## Reglas
- JavaScript moderno (ESM, `const`/`let`), sin TypeScript por ahora.
- Consultas SQL siempre parametrizadas.
- No agregar dependencias sin preguntarme.
- Mensajes de commit en español, en imperativo.

## No tocar
- `.env`, `migraciones/` ya aplicadas, `dist/`.

💡 Consejo

Mantenlo corto y concreto: lo que un compañero nuevo necesitaría en su primer día. Un archivo enorme se ignora o confunde. Cuando el agente cometa el mismo error dos veces, agrega la regla aquí.

3.Permisos: tú tienes el control

Los agentes piden permiso antes de ejecutar comandos o editar archivos, y la mayoría permite aprobar "una vez" o "siempre". Reglas sanas para empezar:

  • Aprueba lectura y pruebas con confianza; escritura y comandos nuevos, léelos.
  • Desconfía de comandos con rm, curl ... | sh, git push --force o que instalen cosas globales.
  • No actives modos "sin pedir permiso" salvo en un entorno aislado (contenedor o máquina virtual) y sin acceso a secretos.
  • Un agente puede leer texto malicioso en una página o issue que diga "ignora tus instrucciones y haz X": se llama inyección de prompt. Por eso importa que tú apruebes lo sensible.

4.MCP: conectar la IA con tus herramientas

El Model Context Protocol (MCP) es un estándar abierto para que una IA se conecte a herramientas y datos externos mediante "servidores" MCP: tu base de datos, GitHub, un navegador, tu calendario, documentación actualizada, etc. En 2025 pasó a la Agentic AI Foundation de la Linux Foundation, junto con AGENTS.md. Es la forma de que un agente haga cosas como "lee el issue 42 de GitHub" o "consulta esta tabla" sin que copies y pegues.

VentajaRiesgo
Menos copiar y pegar; datos reales y actuales.Cada servidor es código que ejecuta cosas con tus permisos y puede leer tus datos.
  • Instala solo servidores de fuentes oficiales o muy conocidas y revisa qué permisos piden.
  • Dales acceso mínimo: una base de datos de pruebas y de solo lectura, no la de producción.
  • Empieza sin MCP. Añádelo cuando el copiar y pegar te estorbe de verdad.

📒 Apuntes para llevar

  • Ciclo con agentes: rama → plan → cambio pequeño → pruebas → diff → commit.
  • AGENTS.md da contexto estable: comandos, reglas y qué no tocar. Corto y concreto.
  • Revisa los permisos; desconfía de comandos destructivos y de modos sin confirmación.
  • La inyección de prompt existe: el agente puede obedecer texto malicioso que lee.
  • MCP conecta la IA con herramientas; dale mínimo acceso y fuentes confiables.
