CRUD completo en el front

  • ⏱ 100 minutos
  • 📶 Nivel: intermedio
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Listar, crear, editar y borrar con la API, con estados de carga y error.
  • Evitar estados inconsistentes con una pequeña capa de datos.

La pantalla principal de cualquier sistema es un CRUD (crear, leer, actualizar, borrar). La clave es no inventar estado local contradictorio con el del servidor: el servidor es la fuente de la verdad.

jsx
import { useEffect, useState } from "react";
import { api } from "./api";

export function useCitas() {
  const [citas, setCitas] = useState([]);
  const [estado, setEstado] = useState("cargando");   // cargando | listo | error
  const [error, setError] = useState("");

  async function recargar() {
    try { setCitas(await api.citas.listar()); setEstado("listo"); }
    catch (e) { setError(e.message); setEstado("error"); }
  }
  useEffect(() => { recargar(); }, []);

  async function crear(datos) {
    const nueva = await api.citas.crear(datos);                  // lanza si hay error (lo muestra el formulario)
    setCitas((c) => [...c, nueva].sort((a, b) => a.fecha.localeCompare(b.fecha)));
  }
  async function cambiarEstado(id, nuevo) {
    const previo = citas;
    setCitas((c) => c.map((x) => (x.id === id ? { ...x, estado: nuevo } : x)));   // optimista
    try { await api.citas.estado(id, nuevo); }
    catch { setCitas(previo); }                                   // revertir si falla
  }
  async function borrar(id) {
    await api.citas.borrar(id);
    setCitas((c) => c.filter((x) => x.id !== id));
  }
  return { citas, estado, error, recargar, crear, cambiarEstado, borrar };
}

1.Actualización optimista

Cambias la pantalla de inmediato (se siente rápido) y, si el servidor rechaza, revertes. Úsala en acciones de bajo riesgo (marcar completada); para pagos o borrados importantes espera la confirmación.

2.Mostrar errores de validación del servidor

La API devuelve detalle: { cliente: ["..."] }. Muéstralos junto a cada campo:

jsx
{error?.detalle?.cliente && <small role="alert">{error.detalle.cliente[0]}</small>}

3.Un solo "pedir" y librerías de datos

Cuando la app crece (caché, reintentos, recarga al volver a la pestaña, paginación), se usa TanStack Query, que gestiona carga, error y caché por ti. Primero entiende el patrón manual; luego esa librería será obvia.

4.Accesibilidad y detalles

  • Confirmar borrados (diálogo <dialog> accesible, no alert).
  • Botones con texto o aria-label ("Cancelar cita de Ana").
  • Evitar doble envío: deshabilita el botón mientras envía.
  • Formatear fechas con Intl.DateTimeFormat("es-PE").

5.Los cuatro estados de toda pantalla de datos

Una pantalla no es solo "la lista". Diseña siempre estos cuatro casos:

EstadoQué mostrar
CargandoUn esqueleto o "Cargando citas…" (con aria-live="polite")
ErrorMensaje claro y un botón "Reintentar" que llame a recargar()
Vacío"Aún no tienes citas" con un botón para crear la primera
ListoLa lista, con acciones
jsx
function Citas() {
  const { citas, estado, error, recargar, borrar } = useCitas();
  if (estado === "cargando") return <p aria-live="polite">Cargando citas…</p>;
  if (estado === "error") return <div role="alert"><p>{error}</p><button onClick={recargar}>Reintentar</button></div>;
  if (citas.length === 0) return <p>Aún no tienes citas. Crea la primera.</p>;
  return <ul>{citas.map((c) => <li key={c.id}>{c.cliente} · {c.fecha}</li>)}</ul>;
}

6.Formulario de creación con errores por campo

jsx
function FormCita({ alCrear }) {
  const [errores, setErrores] = useState({});
  const [enviando, setEnviando] = useState(false);

  async function enviar(e) {
    e.preventDefault();
    const f = new FormData(e.currentTarget);
    setEnviando(true); setErrores({});
    try {
      await alCrear({ cliente: f.get("cliente"), fecha: f.get("fecha") });
      e.currentTarget.reset();
    } catch (err) {
      setErrores(err.detalle ?? { general: [err.message] });
    } finally {
      setEnviando(false);
    }
  }
  return (
    <form onSubmit={enviar} noValidate>
      <label>Cliente <input name="cliente" aria-invalid={!!errores.cliente} /></label>
      {errores.cliente && <small role="alert">{errores.cliente[0]}</small>}
      <label>Fecha y hora <input name="fecha" type="datetime-local" /></label>
      {errores.fecha && <small role="alert">{errores.fecha[0]}</small>}
      <button disabled={enviando}>{enviando ? "Guardando…" : "Agendar"}</button>
    </form>
  );
}

7.Filtros y búsqueda: en el servidor o en el front

  • Pocos datos (menos de unos cientos): trae todo y filtra en el front con filter. Es instantáneo.
  • Muchos datos: manda los filtros a la API como parámetros (?estado=pendiente&q=ana&pagina=2) y deja que la base de datos filtre. Así no descargas miles de filas.
  • Guarda los filtros en la URL (useSearchParams) y podrás compartir o recargar sin perderlos.

8.Cuándo NO usar actualización optimista

Si el servidor puede rechazar por una regla de negocio importante (por ejemplo, "esa hora ya está ocupada"), espera la respuesta antes de cambiar la pantalla. Mostrar "Cita confirmada" y luego revertirla confunde más que esperar medio segundo.

9.Probar los casos difíciles

  • Apaga la API y recarga: ¿ves el error con "Reintentar"?
  • Envía el formulario vacío: ¿cada campo muestra su mensaje?
  • Haz doble clic rápido en "Agendar": ¿se crea solo una cita?
  • Borra la última cita: ¿aparece el estado vacío?

📒 Apuntes para llevar

  • El servidor es la fuente de la verdad; el estado local solo la refleja.
  • Toda pantalla de datos tiene cuatro estados: cargando, error, vacío y listo.
  • Actualización optimista solo en acciones de bajo riesgo, con reversión si falla.
  • Los errores de validación del servidor se muestran junto a cada campo.
  • Deshabilita el botón mientras envía para evitar duplicados.
