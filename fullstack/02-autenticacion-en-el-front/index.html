Autenticación en el front

  • ⏱ 100 minutos
  • 📶 Nivel: intermedio
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Guardar el usuario en un contexto de React.
  • Proteger rutas y manejar sesiones expiradas.

El front no "autentica": solo refleja si el servidor te reconoce. La seguridad real vive en la API; el front decide qué pantalla mostrar. Ocultar un botón no protege nada.

1.Contexto de sesión

Al cargar la app, pregunta al servidor "¿quién soy?". Añade a tu API una ruta GET /api/yo (protegida con exigirSesion) que devuelva { id, correo }.

jsx
// src/Sesion.jsx
import { createContext, useContext, useEffect, useState } from "react";
import { api, ErrorApi } from "./api";

const Ctx = createContext(null);
export const useSesion = () => useContext(Ctx);

export function ProveedorSesion({ children }) {
  const [usuario, setUsuario] = useState(null);
  const [cargando, setCargando] = useState(true);

  useEffect(() => {
    api.yo().then(setUsuario).catch(() => setUsuario(null)).finally(() => setCargando(false));
  }, []);

  async function entrar(credenciales) {
    await api.login(credenciales);
    setUsuario(await api.yo());
  }
  async function salir() {
    await api.logout();
    setUsuario(null);
  }
  return <Ctx.Provider value={{ usuario, cargando, entrar, salir }}>{children}</Ctx.Provider>;
}

(Añade a api: yo: () => pedir("/api/yo").)

2.Rutas protegidas

jsx
import { Navigate, Outlet, useLocation } from "react-router";
import { useSesion } from "./Sesion";

export function RutaPrivada() {
  const { usuario, cargando } = useSesion();
  const ubicacion = useLocation();
  if (cargando) return <p>Cargando…</p>;
  return usuario ? <Outlet /> : <Navigate to="/login" state={{ desde: ubicacion }} replace />;
}

3.Formulario de login con errores

jsx
function Login() {
  const { entrar } = useSesion();
  const navegar = useNavigate();
  const [error, setError] = useState("");
  const [enviando, setEnviando] = useState(false);

  async function enviar(e) {
    e.preventDefault();
    const f = new FormData(e.currentTarget);
    setEnviando(true); setError("");
    try {
      await entrar({ correo: f.get("correo"), clave: f.get("clave") });
      navegar("/citas");
    } catch (err) {
      setError(err instanceof ErrorApi && err.estado === 429 ? "Demasiados intentos. Espera unos minutos." : err.message);
    } finally {
      setEnviando(false);
    }
  }
  return (
    <form onSubmit={enviar}>
      <label>Correo <input name="correo" type="email" required autoComplete="username" /></label>
      <label>Clave <input name="clave" type="password" required minLength={8} autoComplete="current-password" /></label>
      <button disabled={enviando}>{enviando ? "Entrando…" : "Entrar"}</button>
      {error && <p role="alert">{error}</p>}
    </form>
  );
}

4.Sesión expirada

Si una petición devuelve 401 en medio del uso, la sesión caducó: limpia el usuario y redirige a login. Una forma: que pedir lance un evento o que cada llamada capture ErrorApi con estado 401.

5.Experiencia de usuario

  • Estados cargando / error / vacío / éxito en cada pantalla.
  • autoComplete correcto para que los gestores de contraseñas funcionen.
  • Mensajes de error claros pero no reveladores.
  • Accesibilidad: role="alert" para anunciar errores, foco al primer campo con error.

7.Volver a donde ibas tras el login

La ruta privada guardó la ubicación en state.desde. Después de entrar, léela y redirige allí:

jsx
const ubicacion = useLocation();
const destino = ubicacion.state?.desde?.pathname ?? "/citas";
// ...
await entrar({ correo, clave });
navegar(destino, { replace: true });

8.Cerrar sesión y expirar de verdad

  • Al salir, llama a POST /api/logout (el servidor borra la sesión) y limpia el usuario del contexto.
  • Si el usuario tiene varias pestañas, la otra seguirá mostrando datos hasta su próxima petición; el 401 la sacará. Es normal.
  • Borra del estado cualquier dato privado al salir (lista de citas, clientes) para que no se vea si entra otra persona en el mismo equipo.

9.Manejar el 401 en un solo lugar

js
// en api.js, dentro de pedir():
if (r.status === 401 && ruta !== "/api/login" && ruta !== "/api/yo") {
  window.dispatchEvent(new Event("sesion-expirada"));
}

// en ProveedorSesion:
useEffect(() => {
  const alExpirar = () => setUsuario(null);
  window.addEventListener("sesion-expirada", alExpirar);
  return () => window.removeEventListener("sesion-expirada", alExpirar);
}, []);

Como la ruta privada depende de usuario, al ponerlo en null React te lleva a /login sin más código.

10.Roles: mostrar según el rol (con cuidado)

Si tu API devuelve rol ("admin" o "recepcion"), puedes ocultar opciones. Es solo comodidad: la API debe volver a comprobar el rol en cada ruta. Un usuario curioso puede cambiar el JavaScript de su navegador, pero no puede saltarse el servidor.

jsx
function SoloAdmin({ children }) {
  const { usuario } = useSesion();
  return usuario?.rol === "admin" ? children : null;
}

11.Errores frecuentes

  • Guardar la sesión en localStorage: cualquier script (XSS) puede leerla. La cookie HttpOnly no es legible desde JavaScript.
  • No esperar a cargando: redirigir antes de saber si hay sesión manda al login a usuarios que sí la tienen.
  • Mensajes distintos para "correo no existe" y "clave incorrecta": revelan qué correos están registrados.

📒 Apuntes para llevar

  • El front solo refleja la sesión; la seguridad vive en la API.
  • Al cargar, pregunta GET /api/yo y guarda el resultado en un contexto.
  • Mientras cargando sea true, no redirijas.
  • Un 401 en medio del uso significa sesión caducada: limpia el usuario y vuelve a login.
  • Nunca guardes la sesión en localStorage; usa cookie HttpOnly.

12.Glosario

TérminoSignificado
