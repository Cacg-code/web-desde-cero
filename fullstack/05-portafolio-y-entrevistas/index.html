Del curso al trabajo: portafolio y entrevistas

  • ⏱ 90 minutos
  • 📶 Nivel: básico
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Armar un portafolio que demuestre capacidad.
  • Prepararte para pruebas técnicas y conversaciones de trabajo.

Saber programar no basta: hay que demostrarlo. Los reclutadores y clientes miran poco tiempo; dales rápido evidencia.

1.Portafolio

  • 3–5 proyectos de calidad, no 20 mediocres: uno de maquetación impecable, uno con JavaScript puro, uno en React y el full-stack con login y base de datos.
  • Cada uno: captura/GIF, enlace en vivo, enlace al código, qué problema resuelve, tecnologías y qué aprendiste o decidiste.
  • README cuidado, commits ordenados, pruebas y despliegue funcionando.
  • Una página propia rápida, accesible, responsive, con contacto visible.

2.GitHub y LinkedIn

Perfil de GitHub con README, repos fijados, actividad constante. LinkedIn con titular claro ("Desarrollador web front-end/full-stack | React · Node"), proyectos y enlaces. Escribe de lo que aprendes: publicar un pequeño artículo o hilo mensual construye reputación.

3.Entrevistas técnicas

  • Conceptos: cómo funciona la web (HTTP, DNS), el modelo de caja, flexbox/grid, closures, this, promesas/async, el DOM, eventos, ciclo de vida en React, REST, SQL, JWT/cookies, XSS/CSRF.
  • Práctica en vivo: pequeños ejercicios (filtrar un array, maquetar una tarjeta, consumir una API). Habla en voz alta lo que piensas.
  • Proyectos: te preguntarán decisiones ("¿por qué elegiste X?"); conoce bien lo tuyo.
  • Algoritmos: arrays, strings, hash maps, recursión; practica en plataformas como Exercism, Codewars o LeetCode.
  • Inglés técnico: lee documentación y practica explicar tus proyectos.

4.Caminos

Empleo en empresa (junior), freelance (siguiente lección), producto propio, remoto internacional. Lo más importante al inicio: experiencia real acumulada (proyectos para negocios, contribuciones a código abierto, prácticas).

5.Después de este curso

TypeScript en profundidad, Next.js, PostgreSQL avanzado, Docker y despliegues, pruebas end-to-end (Playwright), patrones de diseño, arquitectura. El aprendizaje no termina: lo importante es construir cosas constantemente.

6.Anatomía de un README que vende

  1. Título y una frase: qué es y para quién ("Sistema de citas para barberías").
  2. Captura o GIF en la primera pantalla.
  3. Enlace en vivo y usuario de prueba si hay login.
  4. Tecnologías en una línea.
  5. Cómo ejecutarlo en 3–5 comandos.
  6. Decisiones técnicas: por qué elegiste X (esto es lo que preguntan en entrevistas).
  7. Qué mejorarías con más tiempo: muestra criterio.

7.Plantilla de descripción de proyecto

## Sistema de citas para barberías

8.Tu CV técnico en una página

  • Titular claro y enlaces (portafolio, GitHub, LinkedIn).
  • Proyectos primero, con resultados verificables ("reduce de 5 a 1 clic el flujo de reserva").
  • Tecnologías agrupadas, sin inventar niveles ("avanzado en todo" no convence).
  • Una sola página, en PDF, con texto real (no imagen) para que los sistemas de selección lo lean.

9.Cómo preparar una entrevista en una semana

DíaQué hacer
1Repasa tus 3 proyectos: cada decisión y cada problema que resolviste
2Conceptos web: HTTP, DNS, cookies, CORS, REST
3JavaScript: closures, this, promesas, eventos
4React: estado, efectos, renderizado, claves
5SQL y seguridad básica (inyección, XSS, contraseñas)
6Dos ejercicios de código en voz alta, con cronómetro
7Simulacro completo y preguntas que tú harás a la empresa

10.Preguntas frecuentes (y cómo pensarlas)

  • "Cuéntame de un bug difícil." Estructura: contexto → síntoma → cómo lo investigaste → causa → qué cambiaste para que no vuelva.
  • "¿Por qué React y no HTML simple?" Responde según el problema: estado complejo, componentes reutilizables, equipo.
  • "No sé." Es válido si sigues con "pero lo abordaría así…". Inventar es peor.

11.Aprender en público

Un artículo corto al mes ("Cómo arreglé un error de CORS con cookies") te obliga a entender de verdad y deja evidencia pública. No necesita ser perfecto: necesita ser honesto y útil.

📒 Apuntes para llevar

  • Pocos proyectos buenos valen más que muchos mediocres.
  • Cada proyecto: captura, demo, código, problema, tecnologías y decisiones.
  • El README es tu primera entrevista.
  • En entrevistas te preguntan el porqué de tus decisiones: conoce bien lo tuyo.
  • La experiencia real (clientes, código abierto) pesa más que otro curso.
