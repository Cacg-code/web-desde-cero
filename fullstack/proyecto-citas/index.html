Proyecto: sistema de citas full-stack

  • ⏱ ≈ 10 horas
  • 📶 Nivel: avanzado
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Unir front en React y API propia en un producto completo y publicado.
  • Trabajar como en un proyecto real: requisitos, pruebas, despliegue y documentación.

Este es tu proyecto final de desarrollo web: el sistema de citas de un negocio (una barbería, un consultorio, un spa) con panel de administración y página pública. Es el tipo de trabajo que puedes vender.

1.Funcionalidades mínimas

  • Página pública del negocio: servicios con precios, horarios, mapa, botón de WhatsApp y formulario para pedir cita (sin cuenta).
  • Panel privado (login): agenda por día/semana, crear/editar/cancelar citas, clientes con historial, servicios y precios.
  • Reglas: sin solapamientos, horarios de atención, duración por servicio, estados de la cita.
  • Reporte: ingresos del mes por servicio y clientes más frecuentes.
  • Avisos: recordatorio por correo o enlace de WhatsApp preescrito.

2.Requisitos técnicos

  • React + Vite + React Router; diseño responsive y accesible (teclado, contraste, etiquetas).
  • API Express con las prácticas de la Parte 2; PostgreSQL o SQLite persistente; migraciones.
  • Pruebas: Vitest en la lógica del front y node:test en la API (≥ 20 en total); CI en GitHub Actions.
  • Seguridad revisada con la lista de b9; sin secretos en el repo; HTTPS y dominio.
  • Rendimiento: Lighthouse ≥ 90 en Rendimiento, Accesibilidad, Buenas prácticas y SEO en la página pública.
  • README con capturas, decisiones técnicas, cómo ejecutarlo y datos de prueba.

3.Cómo trabajarlo (método)

  1. Diseña pantallas en papel/Figma y el diagrama de la base de datos.
  2. Divide en historias pequeñas ("el dueño puede crear una cita") y hazlas una por una, cada una con su commit y, si puedes, su rama + pull request.
  3. Entrega un MVP pronto (login + crear/listar citas) y mejóralo en iteraciones.
  4. Prueba con una persona real y corrige lo que le confunda.

💡 Consejo

Si lo terminas bien, tienes el producto base para ofrecer a negocios (con tu portafolio) y una pieza fuerte para entrevistas.

4.Esquema de la base de datos (punto de partida)

sql
CREATE TABLE usuarios (
  id INTEGER PRIMARY KEY,
  correo TEXT NOT NULL UNIQUE,
  clave_hash TEXT NOT NULL,
  rol TEXT NOT NULL DEFAULT 'recepcion' CHECK (rol IN ('admin','recepcion'))
);
CREATE TABLE clientes (
  id INTEGER PRIMARY KEY,
  nombre TEXT NOT NULL,
  telefono TEXT,
  foto TEXT
);
CREATE TABLE servicios (
  id INTEGER PRIMARY KEY,
  nombre TEXT NOT NULL,
  duracion_min INTEGER NOT NULL CHECK (duracion_min > 0),
  precio_centimos INTEGER NOT NULL CHECK (precio_centimos >= 0)
);
CREATE TABLE citas (
  id INTEGER PRIMARY KEY,
  cliente_id INTEGER NOT NULL REFERENCES clientes(id),
  servicio_id INTEGER NOT NULL REFERENCES servicios(id),
  inicio TEXT NOT NULL,            -- ISO 8601: 2026-11-05T15:30
  fin TEXT NOT NULL,
  estado TEXT NOT NULL DEFAULT 'pendiente'
    CHECK (estado IN ('pendiente','confirmada','cancelada','atendida'))
);

Guarda el dinero en céntimos enteros (nunca decimales flotantes) y las fechas en formato ISO.

5.La regla central: sin solapamientos

Dos citas se solapan si una empieza antes de que termine la otra. Esta es la comprobación, tanto en SQL como en una función pura que puedes probar:

js
// función pura (fácil de probar con node:test)
export function seSolapan(a, b) {
  return a.inicio < b.fin && b.inicio < a.fin;
}

// en SQL: ¿hay alguna cita que choque con [nuevoInicio, nuevoFin)?
// SELECT 1 FROM citas
// WHERE estado <> 'cancelada' AND inicio < :nuevoFin AND fin > :nuevoInicio;

Verifica la regla dentro de una transacción para que dos personas reservando a la vez no consigan la misma hora.

7.Plan en seis hitos

  1. Hito 1: base de datos, API de servicios y página pública que los muestra.
  2. Hito 2: login, /api/yo y rutas protegidas.
  3. Hito 3: CRUD de citas con la regla de solapamiento y sus pruebas.
  4. Hito 4: formulario público de cita y recordatorio por WhatsApp (enlace wa.me con texto).
  5. Hito 5: reporte, roles y subida de foto de cliente.
  6. Hito 6: pruebas, CI, Lighthouse, despliegue, dominio y README.

9.Cómo presentarlo a un cliente real

Prepara un recorrido de dos minutos: la página pública desde el celular, pedir una cita, ver la cita en el panel, cambiar su estado y el reporte del mes. Si lo grabas, tienes la pieza central de tu portafolio y de tu mensaje de ventas (ver la lección de freelance).

📒 Apuntes para llevar

  • El MVP es la versión mínima que ya entrega valor: publícalo pronto y mejóralo.
  • La regla de solapamiento es el corazón del sistema y se prueba con una función pura.
  • Dinero en céntimos enteros; fechas en ISO 8601.
  • Trabaja en historias pequeñas, cada una con su commit.
  • Prueba con una persona real y corrige lo que le confunda.
