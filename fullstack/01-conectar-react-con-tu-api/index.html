Conectar React con tu API

  • ⏱ 100 minutos
  • 📶 Nivel: intermedio
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Llamar a la API desde React con cookies de sesión.
  • Configurar el proxy de Vite y CORS correctamente.

Ya tienes un front (React) y un back (Express). El full-stack es hacer que se hablen de forma segura. Dos piezas: cómo se hacen las peticiones y cómo se permiten.

1.Un cliente de API único

Centraliza los fetch en un archivo: un solo lugar para la URL base, los errores y las cookies.

js
// src/api.js
const BASE = import.meta.env.VITE_API_URL ?? "";          // vacío = mismo origen (usa el proxy en desarrollo)

export class ErrorApi extends Error {
  constructor(estado, cuerpo) { super(cuerpo?.error ?? "Error " + estado); this.estado = estado; this.detalle = cuerpo?.detalle; }
}

async function pedir(ruta, { metodo = "GET", cuerpo } = {}) {
  const r = await fetch(BASE + ruta, {
    method: metodo,
    credentials: "include",                                // envía y recibe la cookie de sesión
    headers: cuerpo ? { "Content-Type": "application/json" } : undefined,
    body: cuerpo ? JSON.stringify(cuerpo) : undefined,
  });
  const datos = r.status === 204 ? null : await r.json().catch(() => null);
  if (!r.ok) throw new ErrorApi(r.status, datos);
  return datos;
}

export const api = {
  registro: (c) => pedir("/api/registro", { metodo: "POST", cuerpo: c }),
  login:    (c) => pedir("/api/login", { metodo: "POST", cuerpo: c }),
  logout:   () => pedir("/api/logout", { metodo: "POST" }),
  citas: {
    listar: () => pedir("/api/citas"),
    crear:  (c) => pedir("/api/citas", { metodo: "POST", cuerpo: c }),
    estado: (id, estado) => pedir("/api/citas/" + id, { metodo: "PATCH", cuerpo: { estado } }),
    borrar: (id) => pedir("/api/citas/" + id, { metodo: "DELETE" }),
  },
};

2.Opción A: proxy de Vite (recomendada en desarrollo)

El navegador cree que front y API son el mismo origen (localhost:5173), y Vite reenvía /api a Express. Así no hay problemas de CORS ni de cookies en desarrollo.

js
// vite.config.js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  server: { proxy: { "/api": "http://localhost:3000" } },
});

3.Opción B: orígenes distintos (producción típica)

Front en https://citas.midominio.com y API en https://api.midominio.com. Entonces:

  • En el front: VITE_API_URL=https://api.midominio.com y credentials: "include".
  • En la API: cors({ origin: "https://citas.midominio.com", credentials: true }) (origen exacto, jamás *).
  • Cookie con secure: true. Si ambos comparten el dominio base (midominio.com), SameSite=Lax funciona porque son del mismo "sitio". Si son dominios totalmente distintos necesitarías SameSite=None y los navegadores bloquean cada vez más las cookies de terceros: evita ese diseño.

Otra alternativa: servir el front compilado desde la misma app Express (app.use(express.static("dist"))) y tener un único origen y un único despliegue; es la opción más simple para proyectos pequeños.

4.Variables de entorno en Vite

Solo las que empiezan con VITE_ llegan al navegador, y por eso son públicas. Nunca pongas allí claves privadas.

5.Depurar la conexión

Pestaña Network de DevTools: ¿la petición salió?, ¿qué estado devolvió?, ¿viaja la cookie (Request Headers → Cookie)?, ¿la respuesta trae Set-Cookie? Un error de CORS aparece en consola y la petición se ve "bloqueada".
