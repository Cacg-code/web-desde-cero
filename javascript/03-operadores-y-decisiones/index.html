⚠️ Importante · Regla de oro

Usa siempre === y !==. == y != hacen conversiones que producen resultados difíciles de predecir y son fuente habitual de errores.

Verdadero y falso («truthy» y «falsy»)

En una condición, JavaScript trata algunos valores como falsos aunque no sean false. Los valores falsos son solo estos seis: false, 0, "", null, undefined y NaN. Todo lo demás es verdadero.

📌 Nota · || frente a ??

a || b usa b si a es cualquier valor falso (incluido 0 o ""). a ?? b usa b solo si a es null o undefined. Para valores por defecto, ?? suele ser lo correcto.

4.Tomar decisiones: if, else if y else

La estructura básica
if (condicion) {
  // se ejecuta si la condición es verdadera
} else if (otraCondicion) {
  // se ejecuta si la primera falló y esta es verdadera
} else {
  // se ejecuta si ninguna fue verdadera
}

Cambia el valor de nota y observa qué mensaje aparece. Se evalúan las condiciones de arriba abajo y se ejecuta solo la primera que sea verdadera; por eso el orden importa.

Combinar condiciones

Y, O y NO
const edad = 20, tieneEntrada = true, esVip = false;

if (edad >= 18 && tieneEntrada) { console.log("Puede pasar"); }
if (esVip || edad >= 65)        { console.log("Acceso preferente"); }
if (!tieneEntrada)              { console.log("Debe comprar entrada"); }

5.El operador ternario y el cortocircuito

Cuando solo necesitas elegir entre dos valores, el operador ternario es más breve que un if:

condición ? siEsVerdadera : siEsFalsa
const edad = 20;
const tipo = edad >= 18 ? "adulto" : "menor";
console.log(tipo);                       // "adulto"

console.log(`Tienes ${edad} años y eres ${edad >= 18 ? "mayor" : "menor"} de edad`);

💡 Consejo · Legibilidad primero

Usa el ternario para decisiones simples y de una línea. Si necesitas varias condiciones o varias líneas, un if es más claro. Evita anidar ternarios: son difíciles de leer.

  • Compara con === el valor con cada case.

8.Errores frecuentes

  • Usar = en lugar de === en una condición: if (x = 5) asigna y siempre es verdadero.
  • Usar == y llevarse conversiones sorpresa.
  • Condiciones en el orden equivocado: nota >= 5 antes de nota >= 9 captura todo.
  • Olvidar break en un switch.
  • Comparar textos como si fueran números ("10" < "9" es true).
  • Usar || para valores por defecto y descartar un 0 válido: usa ??.
  • Anidar demasiados if: usa retornos tempranos (if (!valido) return;).
  • Olvidar las llaves en un if con varias instrucciones.

📒 Apuntes para llevar

  • Los operadores aritméticos, de asignación (+=, ++), de comparación y lógicos son la base de toda decisión.
  • Usa siempre === y !==, nunca ==.
  • && = «y», || = «o», ! = «no». Los valores falsos son solo false, 0, "", null, undefined y NaN.
  • ?? aplica un valor por defecto solo si el original es null o undefined.
  • if / else if / else evalúa de arriba abajo y ejecuta solo la primera rama verdadera: el orden importa.
  • El ternario cond ? a : b sirve para elegir entre dos valores en una línea.
  • switch compara un valor con varios casos; cada caso termina con break.
  • return devuelve un valor y termina la función al instante.

Elige una respuesta en cada pregunta. Verás al instante si acertaste y por qué.

¿Qué muestra console.log(5 === "5")?

=== compara también el tipo: número y texto son distintos.

¿Cuál de estos valores es verdadero en una condición?

El texto "0" no está vacío, así que es verdadero. Los falsos son false, 0, "", null, undefined y NaN.

const n = 0; console.log(n || 10) muestra…

0 es falso, así que || devuelve 10. Con ?? se mostraría 0.

Una cadena if / else if evalúa nota >= 5 antes que nota >= 9. ¿Qué problema hay?

Solo se ejecuta la primera rama verdadera: ordena de la condición más estricta a la más general.

Olvidas break en un case de un switch. ¿Qué pasa?

Sin break, la ejecución «cae» al caso siguiente.
