1.Síncrono y asíncrono

Hasta ahora, cada línea esperaba a que terminara la anterior: es lo síncrono. Pero hay tareas que tardan: pedir datos a un servidor, esperar 3 segundos, leer un archivo. Si JavaScript se quedara esperando sin hacer nada más, la página se congelaría: no podrías ni pulsar un botón.

La solución es lo asíncrono: se inicia la tarea lenta, el programa sigue con lo demás, y cuando la tarea termina, se ejecuta una función con el resultado.

Ejecútalo: el mensaje 2 sale antes que el 3, aunque esté escrito después. setTimeout no detiene el programa: agenda la función para más tarde y continúa. Entender esto es la clave de toda la lección.

📌 Nota · Una sola línea de ejecución

JavaScript hace una cosa a la vez. Lo asíncrono no significa «dos cosas a la vez»: significa que cuando una tarea tiene que esperar (a la red, a un temporizador), el navegador se ocupa de la espera y JavaScript atiende otras cosas mientras tanto.

3.Promesas

Una promesa (*Promise*) es un objeto que representa un resultado que llegará en el futuro. Siempre está en uno de tres estados:

EstadoSignificaCómo reaccionar
pending (pendiente)Todavía no hay resultado—
fulfilled (cumplida)Terminó bien y tiene un valor.then(valor => …)
rejected (rechazada)Terminó mal y tiene un error.catch(error => …)
▶ Crear y usar una promesa
Consola
  • .then() recibe el valor cuando la promesa se cumple y devuelve otra promesa: se pueden encadenar.
  • .catch() atrapa los errores de cualquier paso anterior de la cadena.
  • .finally() se ejecuta siempre, salga bien o mal (ideal para quitar un «cargando…»).

5.Pedir datos a internet con fetch

fetch(url) hace una petición HTTP y devuelve una promesa con la respuesta. Es lo que usan las páginas para traer datos de una API (un servicio que ofrece datos en JSON):

El patrón estándar
async function cargarUsuario(id) {
  const respuesta = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);

  if (!respuesta.ok) {                         // 404, 500…
    throw new Error(`Error ${respuesta.status}`);
  }

  const usuario = await respuesta.json();      // convertir el cuerpo JSON en un objeto
  return usuario;
}
  1. await fetch(url) → una respuesta (aunque sea un 404: fetch solo falla si no hay red).
  2. Comprueba respuesta.ok (true para códigos 200–299) y lanza un error si no.
  3. await respuesta.json() → los datos como objeto de JavaScript.
▶ Una API real (necesitas internet)
Consola

📌 Nota · ¿Y si estás sin conexión?

Este ejemplo necesita internet. Si falla, verás el mensaje de error en pantalla: es justo lo que debe pasar, y por eso siempre se envuelve fetch en try…catch. Los ejercicios del curso simulan la red para funcionar siempre.

⚠️ Importante · CORS

Los navegadores bloquean pedir datos a otro dominio salvo que ese servidor lo permita expresamente (cabeceras CORS). Si ves «blocked by CORS policy», no es un error tuyo: el servidor no admite peticiones desde tu página.

Consola

💡 Consejo · No esperes de uno en uno sin necesidad

Si las tareas no dependen unas de otras, lánzalas juntas con Promise.all: tardan lo que tarde la más lenta, no la suma de todas. Es una mejora de rendimiento gratuita.

7.Buena experiencia: cargando, error y vacío

Una pantalla que muestra datos remotos debe contemplar cuatro estados, no solo el feliz:

EstadoQué mostrar
CargandoUn indicador («Cargando…», un *spinner*), idealmente con role="status"
ÉxitoLos datos
VacíoUn mensaje claro («No hay resultados») y no una pantalla en blanco
ErrorQué pasó, en lenguaje humano, y cómo reintentar
Estructura recomendada
async function mostrarDatos() {
  estado.textContent = "Cargando…";
  boton.disabled = true;
  try {
    const datos = await obtener();
    estado.textContent = datos.length ? "" : "No hay resultados";
    pintar(datos);
  } catch (error) {
    estado.textContent = "No pudimos cargar los datos. Inténtalo de nuevo.";
  } finally {
    boton.disabled = false;       // se ejecuta siempre
  }
}

8.Errores frecuentes

  • Olvidar await: obtienes una promesa en lugar del valor (Promise { <pending> }).
  • Usar await fuera de una función async.
  • No comprobar respuesta.ok: un 404 no hace fallar a fetch.
  • Olvidar .json() o no esperarlo con await.
  • No capturar errores: un await que falla sin try/catch deja un error sin controlar.
  • Esperar en serie tareas independientes en lugar de usar Promise.all.
  • Dejar un setInterval activo sin cancelarlo.
  • Usar innerHTML con datos de una API: son datos externos, usa textContent.
  • Dar por hecho que el orden de ejecución es el del código: lo asíncrono llega después.

📒 Apuntes para llevar

  • JavaScript hace una cosa a la vez; lo asíncrono permite iniciar una tarea lenta y seguir, atendiendo el resultado cuando llegue.
  • setTimeout ejecuta una vez y setInterval repetidamente; cancélalos con clearTimeout/clearInterval.
  • Una Promise está pendiente, cumplida o rechazada: .then() recibe el valor, .catch() el error y .finally() siempre se ejecuta.
  • async function devuelve una promesa; await espera el resultado sin congelar la página; try/catch captura los fallos.
  • fetch(url) devuelve la respuesta: comprueba respuesta.ok y usa await respuesta.json().
  • Promise.all lanza tareas independientes en paralelo; allSettled y race cubren otros casos.
  • Toda pantalla con datos remotos necesita estados de cargando, éxito, vacío y error.
  • Los datos de internet son externos: muéstralos con textContent.
