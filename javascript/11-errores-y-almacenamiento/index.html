2.try, catch, finally y throw

Controlar un error
try {
  // código que PUEDE fallar
  const datos = JSON.parse(texto);
  mostrar(datos);
} catch (error) {
  // qué hacer si falla
  console.error("No se pudo leer:", error.message);
} finally {
  // se ejecuta SIEMPRE, haya o no error (limpieza)
  ocultarCargando();
}
PartePara qué
try { … }Código que puede fallar
catch (error) { … }Se ejecuta solo si hubo error; error.message explica qué pasó
finally { … }Se ejecuta siempre: ideal para quitar un «cargando…»
throw new Error("…")Lanzas tú un error cuando algo no es válido

💡 Consejo · Falla pronto y con claridad

Valida los datos al principio de una función y lanza un error con un mensaje útil: «Falta el precio» es mucho mejor que dejar que el programa falle tres funciones después con un críptico NaN. Y captura los errores solo donde puedas hacer algo útil con ellos.

3.Depurar: encontrar el error

Depurar (*debugging*) es el arte de encontrar por qué algo no hace lo que esperas. El método siempre es el mismo:

  1. Reproduce el problema de forma fiable.
  2. Lee el mensaje de error y la línea que indica.
  3. Formula una hipótesis: ¿qué valor creo que tiene cada variable aquí?
  4. Compruébala con console.log o con el depurador.
  5. Corrige una cosa y vuelve a probar.

📌 Nota · Leer una pila de errores

Cuando un error aparece en la consola, la pila (*stack trace*) lista las funciones por las que pasó, de la más reciente (arriba) a la más antigua. Busca la primera línea que sea de tu código: casi siempre ahí está el problema.

4.Guardar datos en el navegador: localStorage

Las variables desaparecen al recargar la página. Para conservar datos (una lista de tareas, una preferencia, un carrito) el navegador ofrece localStorage: un pequeño almacén de pares clave–valor que persiste aunque cierres el navegador.

MétodoQué hace
localStorage.setItem(clave, valor)Guarda un valor (siempre como texto)
localStorage.getItem(clave)Lo lee; devuelve null si no existe
localStorage.removeItem(clave)Borra una clave
localStorage.clear()Borra todo lo guardado por tu sitio

5.Guardar con seguridad

  1. Convierte con JSON al guardar y al leer.
  2. Lee siempre con un valor por defecto: ?? [], porque la primera vez no hay nada.
  3. Envuelve JSON.parse en try/catch: alguien puede haber alterado el dato.
  4. Usa un nombre de clave con prefijo (miapp:tareas) para no chocar con otros datos.
Un par de funciones robustas
const CLAVE = "miapp:tareas";

function leerTareas() {
  try {
    return JSON.parse(localStorage.getItem(CLAVE)) ?? [];
  } catch {
    return [];                        // dato corrupto: empezamos de cero
  }
}

function guardarTareas(tareas) {
  localStorage.setItem(CLAVE, JSON.stringify(tareas));
}

⚠️ Importante · Nunca guardes secretos

localStorage no es seguro: cualquier script de la página (y cualquiera que use ese navegador) puede leerlo. No guardes contraseñas, tokens de acceso ni datos personales sensibles. Úsalo para preferencias y datos sin riesgo.

6.Organizar el código: módulos

Cuando un programa crece, un solo archivo de 800 líneas se vuelve inmanejable. Los módulos de ES dejan dividir el código en archivos con una responsabilidad cada uno, que exportan lo que ofrecen e importan lo que necesitan:

tareas.js (exporta)
const CLAVE = "miapp:tareas";

export function leerTareas() { /* … */ }
export function guardarTareas(tareas) { /* … */ }
export const MAXIMO = 100;

export default function crearTarea(texto) {
  return { id: Date.now(), texto, hecha: false };
}
app.js (importa)
import crearTarea, { leerTareas, guardarTareas, MAXIMO } from "./tareas.js";

const tareas = leerTareas();
tareas.push(crearTarea("Estudiar módulos"));
guardarTareas(tareas);
En el HTML
<script type="module" src="js/app.js"></script>
  • type="module" activa los módulos; ya se comporta como defer.
  • Las variables de un módulo son privadas a él salvo que las exportes.
  • Las rutas de import empiezan con ./ o ../ y llevan la extensión .js.
  • Los módulos no funcionan abriendo el archivo directamente (file://): necesitas un servidor, por ejemplo la extensión Live Server de VS Code.

💡 Consejo · Cómo dividir

Una guía sencilla: un archivo para los datos y su almacenamiento, otro para la lógica (funciones puras) y otro para la interfaz (DOM y eventos). Si dudas, pregúntate: «¿puedo probar esta función sin una página?»

7.Hábitos de código limpio

  • Nombres claros que digan qué hace o qué contiene cada cosa.
  • Funciones pequeñas con una sola tarea.
  • Evita los «números mágicos»: const MAXIMO_TAREAS = 100; en lugar de un 100 suelto.
  • Una sola fuente de verdad: no repitas el mismo dato en dos sitios.
  • Comenta el porqué, no lo evidente.
  • Valida las entradas y trata los errores.
  • Formatea con una herramienta (Prettier) y revisa con un linter (ESLint): encuentran errores antes de ejecutar.
  • Activa el modo estricto ("use strict";, o usa módulos, que ya lo tienen): convierte fallos silenciosos en errores.

📌 Nota · Seguridad básica

Nunca confíes en los datos que llegan de fuera (formularios, URL, APIs): valídalos y, al mostrarlos, usa textContent. Cualquier verificación importante (precios, permisos) debe repetirse en el servidor, porque el código del navegador se puede modificar.

8.Errores frecuentes

  • Guardar objetos sin JSON.stringify: acaban como "[object Object]".
  • Olvidar el valor por defecto al leer: JSON.parse(null) da null y rompe lo que sigue.
  • No usar try/catch con JSON.parse de datos externos.
  • Atrapar un error y no hacer nada (catch {}): oculta los problemas. Al menos regístralo.
  • Guardar secretos en localStorage.
  • Depurar a ciegas: cambiar cosas al azar en vez de comprobar el valor de las variables.
  • Abrir módulos con doble clic (file://) y sorprenderse por los errores de CORS.
  • Modificar el estado y olvidar volver a guardarlo.

📒 Apuntes para llevar

  • Los errores se clasifican (SyntaxError, ReferenceError, TypeError…); la consola indica el tipo, el mensaje y la línea.
  • try { … } catch (error) { … } finally { … } controla los fallos; throw new Error("…") lanza los propios.
  • Valida al principio y falla con mensajes claros; captura solo donde puedas hacer algo útil.
  • Depura con método: reproduce, lee, formula una hipótesis, comprueba y corrige una cosa a la vez.
  • console.table, group, assert, los puntos de interrupción y debugger van mucho más allá de console.log.
  • localStorage guarda texto de forma persistente: usa JSON.stringify/parse y un valor por defecto al leer.
  • No guardes secretos en el navegador; sessionStorage dura una pestaña y las cookies se envían al servidor.
  • Los módulos (import/export, type="module") dividen el código; Prettier, ESLint y los nombres claros lo mantienen sano.

¿Cuándo se ejecuta el bloque finally?

Se ejecuta siempre, haya o no error: ideal para limpiar.

localStorage.setItem("lista", [1, 2, 3]) guarda…

Convierte el valor a texto: para arrays y objetos usa JSON.stringify.

¿Qué devuelve localStorage.getItem("clave") si la clave no existe?

Devuelve null. Por eso se usa ?? valorPorDefecto.
