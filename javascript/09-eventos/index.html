Eventos y formularios

1.Qué es un evento

Un evento es algo que ocurre en la página: un clic, una tecla pulsada, un formulario enviado, la ventana que cambia de tamaño, una imagen que termina de cargar. JavaScript te permite escuchar esos eventos y ejecutar una función cuando suceden. Así la página deja de ser un documento estático y se vuelve interactiva.

La fórmula básica
elemento.addEventListener("tipo-de-evento", funcion);
//            ① qué escuchar    ② qué hacer

La función que pasas se llama manejador (*handler*) o callback. No se ejecuta al escribirla: el navegador la guarda y la llama cada vez que ocurre el evento.

⚠️ Importante · No pongas paréntesis

boton.addEventListener("click", saludar) pasa la función para que el navegador la llame cuando toque. boton.addEventListener("click", saludar()) la ejecuta ya y pasa su resultado. Es el error más común con eventos.

6.Propagación y delegación de eventos

Cuando ocurre un evento en un elemento, «sube» por sus ancestros: primero se avisa al elemento, luego a su padre, a su abuelo… hasta document. A esto se le llama burbujeo (*bubbling*).

Y de ahí sale una técnica muy potente, la delegación de eventos: en lugar de poner un manejador a cada elemento de una lista, pones uno solo en el contenedor y miras e.target para saber cuál se pulsó. Funciona también con los elementos que añadas después.

📌 Nota · closest()

e.target.closest("li") sube desde el elemento pulsado hasta encontrar el li más cercano. Es más robusto que e.target a secas, porque el clic puede caer en un <strong> dentro del <li>.

7.Teclado y accesibilidad

  • Usa <button> para las acciones: funciona con ratón, teclado (Enter, Espacio) y lector de pantalla, sin hacer nada.
  • No pongas click en un <div> o <span>: nadie podrá usarlo con teclado.
  • Para atajos, escucha keydown y comprueba e.key (por ejemplo "Escape" para cerrar).
  • Nunca dependas solo del ratón (mouseover): ofrece también focus.
  • Si cambias algo en la página, avísalo con una región aria-live o role="status".

8.Más opciones de addEventListener

OpciónEfectoEjemplo
{ once: true }El manejador se ejecuta una sola vezboton.addEventListener("click", f, { once: true })
removeEventListenerQuita un manejador (necesita la misma función)boton.removeEventListener("click", f)
{ passive: true }Promete no cancelar (mejora el rendimiento del scroll)addEventListener("scroll", f, { passive: true })
Un manejador nombrado se puede quitar
function saludar() { console.log("¡Hola!"); }

boton.addEventListener("click", saludar);
boton.removeEventListener("click", saludar);     // funciona porque es la misma función

// Con una flecha anónima NO se puede quitar:
boton.addEventListener("click", () => console.log("x"));

💡 Consejo · Debounce

Para eventos que se disparan muchísimas veces (input, scroll, resize), conviene esperar a que el usuario pare antes de hacer algo costoso. Esa técnica se llama *debounce* y se apoya en setTimeout, que verás en la siguiente lección.

9.Errores frecuentes

  • addEventListener("click", funcion()) con paréntesis: se ejecuta de inmediato.
  • Olvidar e.preventDefault() en un submit: la página se recarga y «desaparece» todo.
  • Escuchar click en el botón del formulario en lugar de submit en el formulario.
  • Leer .value como si fuera número: es texto. "2" + "3" es "23".
  • Añadir un manejador por cada elemento de una lista en vez de usar delegación.
  • Esperar que un manejador funcione sobre elementos que aún no existen (usa delegación).
  • Eventos en div sin teclado: inaccesible. Usa button.
  • Manejadores dentro de bucles que acaban duplicados al repintar: se ejecutan varias veces.
  • Atributos como onclick="…" en el HTML: difíciles de mantener.

📒 Apuntes para llevar

  • elemento.addEventListener("evento", funcion) ejecuta tu función cuando ocurre el evento; pasa la función, no la llames.
  • Eventos habituales: click, input, change, submit, keydown, focus, DOMContentLoaded.
  • El objeto del evento (e) da target, key, type… y preventDefault() cancela la acción por defecto.
  • En un formulario escucha submit y llama a e.preventDefault(); lee los campos con .value, .checked o FormData.
  • Los valores de los campos son texto: conviértelos con Number().
  • Valida con mensajes dentro de la página, enlazados con aria-describedby y anunciados con role="alert".
  • Los eventos burbujean: la delegación pone un solo manejador en el contenedor y usa e.target.closest(…).
  • Usa button para acciones, soporta el teclado y evita onclick en el HTML.
