Consultar con SELECT

  • ⏱ 60 minutos

1.SELECT y FROM: pedir columnas

SELECT es la instrucción que más usarás. Su forma mínima tiene dos partes: qué columnas quieres (SELECT) y de qué tabla (FROM). Un asterisco * significa «todas las columnas».

Todas las columnas
SELECT * FROM productos;

Dos herramientas muy útiles al elegir columnas:

  • AS pone un alias (otro nombre) a una columna o a un cálculo.
  • DISTINCT elimina los resultados repetidos.
Cálculos y valores únicos
-- Valor del inventario de cada producto
SELECT nombre, precio * stock AS valor
FROM productos;

-- ¿Qué categorías existen?
SELECT DISTINCT categoria

📌 Nota · Un SELECT no cambia nada

Consultar es de solo lectura: ni SELECT ni los cálculos modifican los datos guardados. Puedes probar todo sin miedo. Los cambios llegan en la lección 3.

2.WHERE: filtrar filas

Sin WHERE obtienes todas las filas. Con WHERE indicas una condición y solo se devuelven las filas que la cumplen.

Productos de más de 100
SELECT nombre, precio
FROM productos
WHERE precio > 100;

Resultado esperado

nombreprecio
Teclado120.00
Monitor FHD650.00
Webcam150.00
Monitor 4K899.00

=igual acategoria = 'Audio'
<> o !=distinto decategoria <> 'Audio'
> · >=mayor que · mayor o igualstock >= 10
< · <=menor que · menor o igualprecio < 50

⚠️ Importante · Texto entre comillas simples

Los valores de texto van entre comillas simples: 'Audio'. Las comillas dobles "…" son para nombres de tablas o columnas, y en PostgreSQL usarlas con un texto da error. Los números van sin comillas. Además, la comparación = con texto distingue mayúsculas de minúsculas: 'audio' no es igual a 'Audio'.

Combinar condiciones: AND, OR, NOT

  • AND: deben cumplirse las dos condiciones.
  • OR: basta con que se cumpla una.
  • NOT: invierte una condición.
Combinaciones
-- Periféricos que tengan stock
SELECT nombre, categoria, stock
FROM productos
WHERE categoria = 'Periféricos' AND stock > 0;

-- Con paréntesis, para que quede claro
SELECT nombre, categoria, precio
FROM productos
WHERE (categoria = 'Audio' OR categoria = 'Pantallas')
  AND precio < 700;

💡 Consejo · Usa paréntesis cuando mezcles AND y OR

AND se evalúa antes que OR, como la multiplicación antes que la suma. Sin paréntesis, a OR b AND c significa a OR (b AND c), y suele no ser lo que querías.

BETWEEN e IN

Dos atajos que hacen las consultas más legibles: BETWEEN comprueba un rango (incluye los dos extremos) e IN comprueba si el valor está en una lista.

Rango y lista
SELECT nombre, precio
FROM productos
WHERE precio BETWEEN 40 AND 100;

SELECT nombre, categoria
FROM productos
WHERE categoria IN ('Audio', 'Accesorios');

3.LIKE: buscar patrones de texto

LIKE busca texto que se parezca a un patrón. Tiene dos comodines:

  • % representa cualquier cantidad de caracteres (también ninguno).
  • _ representa exactamente un carácter.
PatrónEncuentra…
'Monitor%'Textos que empiezan por Monitor
'%or'Textos que terminan en «or»
'%cam%'Textos que contienen «cam»
'Ca_le HDMI'«Cable HDMI», pero el cuarto carácter puede ser cualquiera
Buscar por nombre
SELECT nombre, precio
FROM productos
WHERE nombre LIKE 'Monitor%';

SELECT nombre
FROM productos
WHERE nombre LIKE '%cam%';

Resultado de la primera consulta

nombreprecio
Monitor FHD650.00
Monitor 4K899.00

Resultado de la segunda consulta

nombre
Webcam

⚠️ Importante · Mayúsculas: SQLite y PostgreSQL difieren

En SQLite, LIKE ignora mayúsculas y minúsculas para las letras ASCII ('%cam%' encuentra «Webcam»). En PostgreSQL, LIKE sí distingue mayúsculas: para ignorarlas se usa ILIKE (nombre ILIKE '%cam%').

Valores vacíos: NULL

NULL significa «no hay valor» (dato desconocido o ausente). No es cero ni un texto vacío, y por eso no se compara con =: precio = NULL nunca es verdadero. Se usa IS NULL o IS NOT NULL.

Comparar con NULL
SELECT * FROM productos WHERE precio IS NULL;      -- correcto
SELECT * FROM productos WHERE precio = NULL;       -- NO funciona: nunca devuelve filas

📌 Nota · En nuestra tabla no hay NULL

Las columnas de productos son NOT NULL, así que ninguna consulta de arriba devolvería filas. Lo verás en acción cuando diseñes tus propias tablas en la lección 4.

4.ORDER BY, LIMIT y OFFSET

Una consulta no garantiza ningún orden salvo que lo pidas. ORDER BY ordena el resultado; ASC es ascendente (por defecto) y DESC descendente. Puedes ordenar por varias columnas separándolas con comas.

Ordenar
-- Del más caro al más barato
SELECT nombre, precio
FROM productos
ORDER BY precio DESC;

-- Por categoría y, dentro de cada una, por precio
SELECT categoria, nombre, precio
FROM productos
ORDER BY categoria ASC, precio DESC;

LIMIT restringe cuántas filas se devuelven y OFFSET indica cuántas saltar antes de empezar. Juntos sirven para paginar resultados.

Los tres más caros y la página siguiente
SELECT nombre, precio FROM productos
ORDER BY precio DESC
LIMIT 3;

-- Siguientes tres (página 2)
SELECT nombre, precio FROM productos
ORDER BY precio DESC
LIMIT 3 OFFSET 3;

💡 Consejo · LIMIT casi siempre va con ORDER BY

Sin ORDER BY, «las tres primeras filas» no significan nada concreto: el gestor puede devolverlas en cualquier orden. Para obtener «los tres más caros» ordena primero y limita después.

5.El orden de las cláusulas

Las cláusulas se escriben siempre en este orden. Todas son opcionales salvo SELECT (y FROM cuando se consulta una tabla):

Estructura completa
SELECT   columnas
FROM     tabla
WHERE    condición
ORDER BY columnas
LIMIT    cantidad OFFSET saltar;
  1. FROM: el gestor toma la tabla.
  2. WHERE: se quedan solo las filas que cumplen la condición.
  3. SELECT: se eligen y calculan las columnas.
  4. ORDER BY: se ordena el resultado.
  5. LIMIT / OFFSET: se recorta el resultado.

Esa es la secuencia en la que el gestor piensa la consulta, y explica por qué no puedes usar un alias de SELECT dentro de WHERE.

7.Errores frecuentes


  • Comillas dobles en los textos: WHERE categoria = "Audio" funciona a veces en SQLite por tolerancia, pero en PostgreSQL falla. Usa siempre comillas simples.
  • Comparar con NULL usando =: usa IS NULL o IS NOT NULL.
  • Mezclar AND y OR sin paréntesis: el resultado cambia según la prioridad de los operadores.
  • Usar LIMIT sin ORDER BY: «las primeras filas» no tienen un orden definido.
  • Olvidar el punto y coma al final en la terminal: sqlite3 se queda esperando más texto (aparece ...>). Escribe ; y Enter.
  • Escribir las cláusulas en otro orden: WHERE va antes de ORDER BY, y LIMIT al final.
  • Esperar que LIKE distinga o ignore mayúsculas igual en todos los motores: SQLite lo ignora; PostgreSQL lo distingue (usa ILIKE).





📒 Apuntes para llevar


  • SELECT columnas FROM tabla lee datos y no modifica nada; * significa todas las columnas.
  • AS pone un alias y DISTINCT quita los resultados repetidos.
  • WHERE filtra filas con =, <>, >, <, >=, <=, BETWEEN, IN y LIKE.
  • El texto va entre comillas simples; los números, sin comillas.
  • AND exige las dos condiciones, OR una de ellas; usa paréntesis para mezclarlas.
  • LIKE usa % (cualquier cantidad de caracteres) y _ (uno solo); con NULL se usa IS NULL.
  • ORDER BY col [ASC|DESC] ordena; LIMIT n OFFSET m recorta y pagina.
  • Orden de escritura: SELECT … FROM … WHERE … ORDER BY … LIMIT.
