1.Por qué separar los datos en varias tablas

En la lección 4 viste la regla «un dato, un lugar». Si cada pedido repitiera el nombre y el correo del cliente, un cambio de correo obligaría a tocar muchas filas. La solución es guardar al cliente una sola vez y, en el pedido, solo su id. Ese id escrito en otra tabla se llama clave foránea.

Usaremos cuatro tablas. productos ya la conoces; las otras tres son nuevas (clientes es una versión simplificada de la de la lección 4):

En esta lección y en las siguientes hay 4 clientes (Ana, Luis, Marta y Diego), 4 pedidos y 7 líneas de pedido. Diego todavía no ha comprado nada: lo usaremos para ver qué hace cada tipo de JOIN.

2.Claves foráneas: REFERENCES

Una clave foránea es una columna cuyo valor debe existir como clave primaria en otra tabla. Se declara con REFERENCES:

Tablas relacionadas
CREATE TABLE clientes (
  id     INTEGER PRIMARY KEY,
  nombre TEXT NOT NULL,
  email  TEXT NOT NULL UNIQUE
);

CREATE TABLE pedidos (
  id         INTEGER PRIMARY KEY,
  cliente_id INTEGER NOT NULL REFERENCES clientes(id),
  fecha      TEXT    NOT NULL
);

CREATE TABLE lineas_pedido (
  pedido_id   INTEGER NOT NULL REFERENCES pedidos(id),
  producto_id INTEGER NOT NULL REFERENCES productos(id),
  cantidad    INTEGER NOT NULL CHECK (cantidad > 0),
  PRIMARY KEY (pedido_id, producto_id)
);

Lee cliente_id INTEGER NOT NULL REFERENCES clientes(id) como: «cada pedido pertenece a un cliente que debe existir en clientes». Con esto la base de datos protege la integridad: no deja crear un pedido para un cliente inexistente.

Intento de pedido para un cliente que no existe
INSERT INTO pedidos (cliente_id, fecha)
VALUES (99, '2026-10-05');

Resultado esperado (error real de SQLite):

Error: FOREIGN KEY constraint failed

Lo mismo ocurre al revés: no puedes borrar un cliente que aún tiene pedidos.

Borrar un cliente con pedidos
DELETE FROM clientes WHERE id = 1;

Resultado esperado (error real de SQLite):

Error: FOREIGN KEY constraint failed

⚠️ Importante · SQLite y PostgreSQL

PostgreSQL siempre hace cumplir las claves foráneas. SQLite las ignora por defecto: debes activarlas en cada conexión con PRAGMA foreign_keys = ON;. Los errores de esta lección salen con esa opción activada.

3.Tipos de relaciones

Según cuántas filas de una tabla se asocian con filas de otra, hay tres tipos:

Uno a muchosUn cliente tiene muchos pedidosClave foránea en el lado «muchos»: pedidos.cliente_id
Muchos a muchosUn pedido incluye varios productos y un producto aparece en varios pedidosUna tabla intermedia con dos claves foráneas: lineas_pedido

4.INNER JOIN: unir filas que coinciden

JOIN combina filas de dos tablas según una condición, escrita tras ON. Con INNER JOIN (o solo JOIN) quedan únicamente las filas que tienen pareja en ambas tablas.

Cada pedido con el nombre de su cliente
SELECT c.nombre, p.id AS pedido, p.fecha
FROM clientes c
INNER JOIN pedidos p ON p.cliente_id = c.id
ORDER BY p.id;

c y p son alias de tabla: abreviaturas para no repetir nombres largos y evitar ambigüedades (c.id frente a p.id). AS pedido renombra la columna en el resultado.

Resultado esperado

Ana Torres22026-09-15
Luis Pérez32026-09-20
Marta Ruiz42026-10-02

Diego no aparece: no tiene pedidos, así que no hay pareja para él.

5.LEFT JOIN: conservar todo el lado izquierdo

LEFT JOIN conserva todas las filas de la tabla izquierda (la de FROM) aunque no tengan pareja; en ese caso las columnas de la derecha valen NULL.

Todos los clientes, tengan o no pedidos
SELECT c.nombre, p.id AS pedido, p.fecha
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id
ORDER BY c.id, p.id;

Resultado esperado

nombrepedidofecha
Ana Torres12026-09-01
Ana Torres22026-09-15
Luis Pérez32026-09-20
Marta Ruiz42026-10-02
Diego SotoNULLNULL

Esto permite una consulta muy útil: encontrar lo que no tiene relación, filtrando las filas con NULL en la tabla de la derecha (recuerda usar IS NULL, no = NULL).

Clientes que nunca han comprado
SELECT c.nombre
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id
WHERE p.id IS NULL;

Resultado esperado

nombre
Diego Soto

📌 Nota · ¿Y RIGHT y FULL JOIN?

RIGHT JOIN es el espejo de LEFT JOIN y FULL JOIN conserva ambos lados. PostgreSQL los admite siempre; SQLite solo desde la versión 3.39. En la práctica casi siempre basta con reordenar las tablas y usar LEFT JOIN.

6.Unir tres o más tablas

Puedes encadenar JOIN. Para saber qué contiene el pedido 4 hay que pasar por la tabla intermedia:

Detalle del pedido 4
SELECT p.id AS pedido, pr.nombre AS producto, l.cantidad, pr.precio
FROM pedidos p
JOIN lineas_pedido l ON l.pedido_id  = p.id
JOIN productos pr    ON pr.id        = l.producto_id
WHERE p.id = 4;

8.Errores frecuentes


  • Olvidar la condición ON: sin ella cada fila se combina con todas las de la otra tabla (producto cartesiano) y el resultado explota.
  • Columnas ambiguas: escribir id cuando ambas tablas lo tienen da error. Usa c.id o p.id.
  • Esperar a Diego con INNER JOIN: si quieres conservar filas sin pareja, usa LEFT JOIN.
  • Filtrar el lado derecho de un LEFT JOIN en WHERE: una condición como WHERE p.fecha > '2026-09-10' descarta las filas NULL y lo convierte en un INNER JOIN. Si debe afectar a la unión, ponla en el ON.
  • Comparar con = NULL en lugar de IS NULL: nunca encuentra nada.
  • Olvidar PRAGMA foreign_keys = ON en SQLite: las claves foráneas no se comprueban y puedes crear datos huérfanos.
  • Unir por la columna equivocada (p.id = c.id en lugar de p.cliente_id = c.id): da resultados que parecen válidos pero son incorrectos.





📒 Apuntes para llevar


  • Una clave foránea es una columna que apunta a la clave primaria de otra tabla: cliente_id INTEGER REFERENCES clientes(id).
  • Impide datos huérfanos: no se crea un pedido de un cliente inexistente ni se borra un cliente con pedidos. En SQLite activa PRAGMA foreign_keys = ON.
  • Uno a muchos: la clave foránea va en el lado «muchos». Muchos a muchos: tabla intermedia con dos claves foráneas.
  • INNER JOIN … ON … devuelve solo las filas con pareja en ambas tablas.
  • LEFT JOIN conserva todas las filas de la tabla izquierda; sin pareja, las columnas de la derecha son NULL.
  • LEFT JOIN … WHERE derecha.id IS NULL encuentra filas sin relación (clientes sin pedidos).
  • Usa alias cortos (c, p) y califica las columnas (c.nombre) cuando unes varias tablas.





9.Glosario




TérminoSignificado


Clave foráneaColumna que guarda la clave primaria de una fila de otra tabla para relacionarlas.
Integridad referencialGarantía de que toda clave foránea apunta a una fila que existe.
JOINOperación que combina filas de dos tablas según una condición.
INNER JOINUnión que conserva solo las filas con pareja en ambas tablas.
LEFT JOINUnión que conserva todas las filas de la tabla izquierda; completa con NULL si no hay pareja.
AliasNombre corto temporal para una tabla o columna (clientes c, AS pedido).
Tabla intermediaTabla que implementa una relación muchos a muchos con dos claves foráneas.
Producto cartesianoTodas las combinaciones posibles entre filas de dos tablas; aparece al omitir la condición del JOIN.

Elige una respuesta en cada pregunta. Verás al instante si acertaste y por qué.


¿Qué hace cliente_id INTEGER REFERENCES clientes(id)?
Es una clave foránea: la base de datos rechaza valores que no correspondan a un cliente existente.


¿Cómo se representa una relación muchos a muchos entre pedidos y productos?
La tabla intermedia (lineas_pedido) convierte la relación en dos relaciones uno a muchos.


Con 4 clientes, de los cuales uno no tiene pedidos, ¿qué diferencia hay entre INNER JOIN y LEFT JOIN de clientes a pedidos?
El LEFT JOIN conserva todas las filas de la izquierda; el INNER JOIN solo las que tienen pareja.


¿Cómo encuentras los clientes que nunca han hecho un pedido?
Se unen con LEFT JOIN y se queda con las filas sin pareja usando IS NULL.


¿Qué ocurre si olvidas la condición ON en un JOIN?
Sin condición se obtiene el producto cartesiano: filas de más y sin sentido.
