Git y publicación

  • ⏱ 45 minutos
  • 📶 Nivel: principiante
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Explicar qué son Git, GitHub, repositorio, commit y rama.
  • Crear un repositorio y guardar tus cambios con commits claros.
  • Subir tu proyecto a GitHub con git push.
  • Publicar tu sitio con GitHub Pages.

1.Qué es Git y por qué lo necesitas

Imagina que cada vez que cambias tu página pudieras guardar una fotografía del proyecto con una nota que diga qué hiciste. Si algo se rompe, vuelves a una fotografía anterior. Eso hace Git: un sistema de control de versiones.

ConceptoQué es
GitLa herramienta que corre en tu computadora y guarda el historial del proyecto
GitHubUn sitio web que guarda copias de tus proyectos Git en internet, para compartirlos y publicarlos
RepositorioUna carpeta de proyecto cuyo historial vigila Git
CommitUna «fotografía» del proyecto en un momento, con un mensaje
Rama (branch)Una línea de trabajo; la principal se llama main
Remoto (remote)La copia del repositorio que vive en GitHub, normalmente llamada origin

📌 Nota · Git y GitHub no son lo mismo

Git funciona sin internet y sin cuenta. GitHub es solo uno de los lugares (junto con GitLab o Bitbucket) donde puedes guardar copias. Este curso está publicado en GitHub.

Tres razones para usarlo desde ya:

  1. Puedes equivocarte sin miedo: cada versión anterior se puede recuperar.
  2. Publicas gratis con GitHub Pages, como lo hace este curso.
  3. Es el estándar en el trabajo de programación: aprenderlo ahora te abre puertas.

2.Instalación y configuración

  1. Descarga Git desde git-scm.com e instálalo con las opciones por defecto.
  2. Abre una terminal: en Windows, «Git Bash» (se instala con Git); en Mac y Linux, la aplicación «Terminal». También sirve la terminal integrada de VS Code (Ctrl + `).
  3. Comprueba la instalación con el comando de abajo.
  4. Dile a Git quién eres (solo una vez por computadora).
Comprobar y configurar
git --version
git config --global user.name "Tu Nombre"
git config --global user.email "tu-correo@ejemplo.com"
git config --global init.defaultBranch main

El correo debe ser el mismo de tu cuenta de GitHub, para que tus cambios se asocien contigo. Crea tu cuenta gratuita en github.com.

💡 Consejo · Comandos en una terminal

Los comandos se escriben y se ejecutan con Enter. Con la flecha hacia arriba recuperas el anterior. cd carpeta entra a una carpeta, cd .. sube una y ls (o dir en Windows) lista los archivos.

3.El ciclo de trabajo

Todo lo que harás con Git sigue el mismo recorrido. Entiéndelo bien y el resto son detalles:

Tu carpetaEditas archivos
→git add
Área de preparaciónEliges qué guardar
→git commit
Historial localFotografías guardadas
→git push
GitHubCopia en internet
  • Tu carpeta: donde editas tus archivos de siempre.
  • Área de preparación (staging): eliges qué cambios entran en la próxima «fotografía».
  • Historial local: cada commit queda guardado en tu computadora.
  • GitHub: con git push subes tus commits a internet.

4.Tu primer repositorio

Vamos a convertir una carpeta con tu página en un repositorio. Los comandos se ejecutan dentro de la carpeta del proyecto.

Crear y guardar el primer commit
cd mi-pagina
git init
git status
git add .
git commit -m "Primera versión de mi página personal"
git log --oneline
ComandoQué hace
git initConvierte la carpeta en un repositorio (crea una carpeta oculta .git)
git statusMuestra qué archivos cambiaron o están preparados. Úsalo todo el tiempo
git add archivoPrepara un archivo para el próximo commit; git add . prepara todo
git commit -m "mensaje"Guarda una fotografía con tu mensaje
git log --onelineMuestra el historial resumido
git diffMuestra qué líneas cambiaste desde el último commit

Mensajes de commit que se entienden

MalBien
cambiosAgrega sección de contacto con formulario
arregloCorrige la ruta de la imagen de perfil
asdfMejora el contraste de los enlaces del menú

Un buen mensaje responde a «¿qué hace este cambio?». Dentro de unos meses, tu yo del futuro te lo agradecerá.

5.Subir tu proyecto a GitHub

  1. En GitHub, pulsa New repository. Elige un nombre (por ejemplo mi-pagina), déjalo público y no marques «Add a README» (ya tienes tus archivos).
  2. GitHub te mostrará una dirección como https://github.com/tu-usuario/mi-pagina.git. Cópiala.
  3. En tu terminal, conecta tu carpeta con ese repositorio y sube el historial.
Conectar y subir
git remote add origin https://github.com/tu-usuario/mi-pagina.git
git branch -M main
git push -u origin main
git remote -v
  • git remote add origin … registra la dirección con el nombre origin.
  • git push -u origin main sube la rama main y recuerda la conexión para las próximas veces.
  • git remote -v muestra los remotos configurados.

⚠️ Importante · Autenticación

GitHub ya no acepta la contraseña de tu cuenta en la terminal. La primera vez, te abrirá el navegador para iniciar sesión (con Git Credential Manager, incluido en la instalación de Windows y Mac), o puedes usar un token de acceso personal como contraseña. Nunca compartas tu token ni lo subas a un repositorio.

📌 Nota · Sin terminal

También puedes arrastrar archivos desde la web de GitHub («Add file → Upload files») o usar GitHub Desktop, un programa con botones que hace lo mismo. Conviene aprender la terminal, pero no es la única opción.

6.Publicar con GitHub Pages

GitHub Pages publica gratis los archivos de un repositorio como un sitio web. Es lo que usa este curso.

  1. Abre tu repositorio en GitHub y entra a Settings → Pages.
  2. En Source, elige Deploy from a branch.
  3. Elige la rama main y la carpeta / (root). Pulsa Save.
  4. Espera uno o dos minutos. Arriba verás la dirección: https://tu-usuario.github.io/mi-pagina/.
Si el repositorio se llama…La dirección es…
mi-paginahttps://tu-usuario.github.io/mi-pagina/
tu-usuario.github.iohttps://tu-usuario.github.io/ (tu sitio principal)

⚠️ Importante · Tu index.html

GitHub Pages muestra el archivo index.html de la carpeta raíz. Si tu archivo principal tiene otro nombre, verás un error 404. Y revisa las mayúsculas: en los servidores, Foto.jpg y foto.jpg son archivos distintos.

A partir de ahora, cada vez que hagas git push, GitHub Pages se actualiza solo.

7.Tu rutina de todos los días

El ciclo completo
# 1. Edita tus archivos y pruébalos en el navegador
# 2. Mira qué cambió
git status
# 3. Prepara y guarda
git add .
git commit -m "Describe lo que hiciste"
# 4. Sube a GitHub (y se publica solo)
git push

Si trabajas desde dos computadoras

Traer los cambios
git pull

git pull descarga lo que haya nuevo en GitHub. Hazlo antes de empezar a trabajar.

Ignorar archivos

Hay archivos que no deben subirse (contraseñas, archivos del sistema, carpetas pesadas). Se listan en un archivo llamado .gitignore:

.gitignore
.DS_Store
Thumbs.db
node_modules/
.env
*.log

8.Ramas y colaboración (un vistazo)

Una rama es una línea de trabajo paralela: puedes probar una idea sin tocar main, y si funciona, la unes. Es la base de cómo se colabora.

Trabajar en una rama
git switch -c mejora-menu      # crea y entra a una rama nueva
# …haces cambios y commits…
git push -u origin mejora-menu # sube la rama
git switch main                # vuelve a main

En GitHub, una rama se propone para unirse a main mediante un Pull Request (PR): otras personas ven los cambios, los comentan y, cuando están conformes, los fusionan (merge). Este curso se actualizó justamente así.

📌 Nota · Para empezar basta con main

Si trabajas tú solo en tu página, puedes usar solo main. Cuando colabores con otras personas, las ramas y los PR se vuelven indispensables.

9.Problemas frecuentes

Qué vesQué significa y cómo lo arreglas
fatal: not a git repositoryNo estás dentro de la carpeta del proyecto, o falta git init. Usa cd y verifica con ls -a que exista .git
nothing to commit, working tree cleanNo hay cambios nuevos. Edita algo y vuelve a intentarlo
Author identity unknownFalta git config --global user.name y user.email
rejected … non-fast-forwardGitHub tiene cambios que tú no tienes. Haz git pull y vuelve a git push
remote origin already existsYa conectaste la carpeta. Verifica con git remote -v
Authentication failedCredenciales o token incorrectos. Inicia sesión de nuevo o crea un token
La página en línea no cambiaEspera uno o dos minutos y recarga con Ctrl + F5. Revisa en Actions que el despliegue haya terminado

⚠️ Importante · Nunca subas secretos

No subas contraseñas, tokens ni claves a un repositorio público. Aunque los borres después, quedan en el historial. Si pasa, cambia la clave de inmediato.

📒 Apuntes para llevar

  • Git guarda el historial de tu proyecto; GitHub guarda una copia en internet.
  • Configura tu nombre y correo una vez con git config --global.
  • El ciclo es: editar → git add → git commit -m "…" → git push.
  • git status te dice en qué punto estás; úsalo con frecuencia.
  • Escribe mensajes de commit que expliquen qué hace el cambio.
  • git remote add origin <url> conecta tu carpeta con GitHub; git push -u origin main la sube.
  • GitHub Pages publica tu repositorio desde Settings → Pages (rama main, carpeta / (root)).
  • Las ramas y los Pull Requests permiten probar cambios y colaborar; nunca subas contraseñas.

Elige una respuesta en cada pregunta. Verás al instante si acertaste y por qué.

¿Cuál es la diferencia entre Git y GitHub?

Git es la herramienta de control de versiones. GitHub es un servicio web que aloja repositorios Git.

¿Qué hace git commit -m "mensaje"?

commit guarda en el historial local; para subirlo a GitHub se usa push.

¿En qué orden se hace el ciclo básico?

Primero preparas con add, luego guardas con commit y por último subes con push.

Tu repositorio se llama mi-pagina. ¿Dónde se publica con GitHub Pages?

Los repositorios con nombre normal se publican en una subcarpeta del dominio de tu usuario.

Subiste sin querer una contraseña a un repositorio público. ¿Qué haces?

Aunque la borres, queda en el historial. La única solución segura es cambiar la clave.
