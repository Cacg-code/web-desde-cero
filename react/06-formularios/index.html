Formularios y componentes controlados

  • ⏱ 55 minutos
  • 📶 Nivel: principiante
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Crear campos controlados de todos los tipos.

  • Enviar un formulario con onSubmit.
  • Validar y dar retroalimentación al usuario.

1.Componentes controlados

En HTML normal, un <input> guarda su propio valor: tú lo lees cuando lo necesitas. En React hay una forma más potente: el estado es la única fuente de la verdad y el campo solo muestra lo que dice el estado. A esto se le llama un componente controlado.

<input  
value={nombre}muestra el estado
 
onChange={e => setNombre(e.target.value)}actualiza el estado
/> 
⚛️ Tu primer campo controlado
Consola
  1. El estado nombre guarda el texto.
  2. El campo muestra value={nombre}.
  3. Cada tecla dispara onChange, que actualiza el estado con e.target.value.
  4. React vuelve a dibujar y el campo muestra el valor nuevo.

💡 Consejo · Ventajas

Como el valor vive en el estado, puedes mostrarlo en otras partes (como el saludo y el contador de letras), validarlo, darle formato o borrarlo (setNombre("")) en cualquier momento.

⚠️ Importante · No olvides onChange

Si pones value sin onChange, el campo queda bloqueado: no puedes escribir y React avisa en la consola. Si solo quieres un valor inicial editable, usa defaultValue.

4.Enviar el formulario

Para manejar el envío usa onSubmit en el <form> (no onClick en el botón: así también funciona al pulsar Enter). Siempre empieza con e.preventDefault(); si no, el navegador recarga la página.

5.Validar y dar retroalimentación

Como los datos están en el estado, validar es calcular en cada dibujo si son correctos. No hace falta un estado extra para los errores: se derivan.

⚛️ Validación derivada del estado
Consola
  • Valida al escribir para guiar, y al enviar para asegurar.
  • No muestres errores antes de tiempo: espera a que el campo tenga contenido o haya sido tocado.
  • Deshabilita el botón solo si explicas por qué; mejor muestra el mensaje junto al campo.
  • Recuerda: validar en el navegador mejora la experiencia, pero la validación de seguridad real siempre se hace en el servidor.

6.Errores frecuentes

  • value sin onChange: el campo se bloquea.
  • Usar e.target.value para un checkbox: usa e.target.checked.
  • Olvidar e.preventDefault() en onSubmit: la página se recarga.
  • Valor inicial undefined: empieza siempre con "" (texto), false (casilla) o un valor definido; si no, pasarás de no controlado a controlado y React avisará.
  • Mutar el objeto del formulario: crea siempre una copia con { ...datos, [name]: value }.
  • Convertir números: e.target.value es siempre texto; usa Number(e.target.value) o e.target.valueAsNumber.
  • Olvidar htmlFor/id: los campos sin etiqueta asociada son inaccesibles.

📒 Apuntes para llevar

  • Un campo controlado muestra value del estado y actualiza el estado en onChange.
  • Sin onChange, un campo con value queda bloqueado.
  • Textos, textarea y select usan value; las casillas y radios usan checked.
  • Con muchos campos, guarda un objeto y actualiza con { ...datos, [name]: value }.
  • Usa onSubmit en el <form> y llama a e.preventDefault().
  • La validación se deriva del estado: no necesitas estado extra para los errores.
  • La validación en el navegador es comodidad; la de seguridad va en el servidor.

7.Glosario

TérminoSignificado
Componente controladoCampo cuyo valor lo dicta el estado de React.
onChangeEvento que se dispara cuando cambia el valor de un campo.
e.targetEl elemento que provocó el evento; value y checked salen de él.
preventDefaultCancela la acción por defecto del navegador (por ejemplo, recargar al enviar).
Propiedad calculadaSintaxis { [name]: value } que usa una variable como nombre de propiedad.
ValidaciónComprobar que los datos cumplen las reglas esperadas.

🧠 Comprueba lo aprendido

Elige una respuesta en cada pregunta. Verás al instante si acertaste y por qué.

¿Qué hace controlado a un campo de texto?

El estado es la fuente de verdad; el campo solo refleja ese valor.

¿Qué propiedad lees en un checkbox?

Los checkboxes y radios usan checked.

¿Qué pasa si olvidas e.preventDefault() en onSubmit?

Sin cancelarlo, el navegador hace su envío clásico y recarga.

¿Para qué sirve { ...datos, [name]: value }?

Copia las propiedades existentes y reemplaza únicamente la que corresponde al campo.

e.target.value de un <input type="number">, ¿qué tipo tiene?

Siempre es texto; conviértelo con Number() si lo necesitas.
