Proyecto: carrito de compras

  • ⏱ 150 minutos
  • 📶 Nivel: principiante
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Planificar una aplicación de React dividiéndola en componentes.
  • Combinar useReducer, Context y efectos en un proyecto real.
  • Derivar valores en lugar de duplicarlos en estado.
  • Persistir y recuperar datos del navegador.

1.Qué vas a construir

Vas a crear el carrito de compras de una tienda: un catálogo con buscador, un carrito donde se agregan, suman, restan y quitan productos, un total siempre correcto y el contenido guardado para que no se pierda al recargar. Es un proyecto pequeño, pero tiene la estructura de una aplicación real.

💡 Consejo · Una sola fuente de verdad

El carrito vive en un solo lugar (el reductor del proveedor). El total y el número de artículos no se guardan: se calculan con reduce a partir de las líneas. Así nunca se desincronizan.

📌 Nota · Por qué aria-label

Los botones «−» y «+» no tienen texto que un lector de pantalla pueda leer con claridad. aria-label="Restar" y aria-label="Sumar" describen la acción; además es lo que usan las pruebas para encontrarlos.

4.Paso a paso

Paso 1 · El catálogo

Con PRODUCTOS.map(...) dibuja un <article className="producto"> por producto. Usa key={p.id}. Aún sin carrito: los botones pueden no hacer nada.

Paso 2 · El buscador

Un campo controlado (busqueda) y una lista derivada: PRODUCTOS.filter(p => p.nombre.toLowerCase().includes(busqueda.toLowerCase())). No guardes la lista filtrada en estado.

Paso 3 · El reductor

Esqueleto del reductor
function reductor(lineas, accion) {
  switch (accion.tipo) {
    case "agregar": /* si existe: cantidad + 1; si no: nueva línea con cantidad 1 */
    case "sumar":   /* map: cantidad + 1 en la línea con ese id */
    case "restar":  /* map: cantidad - 1 y filter: descarta las que lleguen a 0 */
    case "quitar":  /* filter: descarta la línea con ese id */
    default: return lineas;
  }
}

Cada caso debe devolver un array nuevo; nunca modifiques el existente.

Paso 4 · Contexto y proveedor

Crea CarritoContext fuera de los componentes. En CarritoProvider usa useReducer(reductor, [], leerGuardado), calcula total y unidades con reduce y ofrécelos junto a lineas y dispatch. Añade el hook useCarrito().

Paso 5 · El carrito

Lee { lineas, dispatch, total }. Si lineas.length === 0 muestra el mensaje de vacío; si no, una <ul className="lineas"> con las líneas y sus tres botones. Muestra el total con moneda(total).

Paso 6 · Persistencia

Dentro del proveedor, un efecto con [lineas] guarda JSON.stringify(lineas) en localStorage. La función leerGuardado (tercer argumento de useReducer) lo recupera al iniciar, con try/catch por si el dato estuviera dañado.

💡 Consejo · Avanza probando

Después de cada paso, ejecuta el editor y comprueba que funciona antes de seguir. Un error aislado es fácil de encontrar; cinco errores mezclados, no.

6.Retos para ir más lejos

  • Filtro por categoría: botones «Todas», «Periféricos» y «Pantallas».
  • Cupón de descuento: un campo que aplique un 10 % si escribes REACT10.
  • Envío gratis: muestra «Te faltan $X para el envío gratis» según el total.
  • Ordenar el catálogo por precio o por nombre (recuerda copiar el array antes de sort).
  • Productos desde una API: reemplaza PRODUCTOS por datos pedidos con el hook useDatos de la lección 10.
  • Pasarlo a un proyecto de Vite, dividir los componentes en archivos y publicarlo en GitHub Pages (lección 11).

8.Errores frecuentes en el proyecto

  • Mutar el estado en el reductor: lineas.push(…) o existe.cantidad++ rompen la actualización. Crea copias con map y filter.
  • Guardar total en estado: se desincroniza. Calcúlalo con reduce.
  • Olvidar .filter(l => l.cantidad > 0) al restar: quedan líneas con cantidad 0 o negativas.
  • Duplicar líneas: al agregar, comprueba primero si el producto ya está.
  • Leer localStorage en cada dibujo: usa el estado inicial perezoso (tercer argumento de useReducer).
  • Olvidar la key en las listas de productos y de líneas.
  • Dar formato en varios sitios: usa una sola función moneda(n).
  • aria-label ausente en los botones «+» y «−».

📒 Apuntes para llevar

  • El proyecto integra componentes, props, listas, estado, formularios, efectos, Context y reductores.
  • Un reductor concentra todas las formas de cambiar el carrito; siempre devuelve un array nuevo.
  • Context comparte lineas, dispatch, total y unidades sin pasar props.
  • Lo que se puede calcular (total, contador, lista filtrada) no se guarda en estado.
  • localStorage + useEffect + estado inicial perezoso dan persistencia.
  • Usa nombres y estructura claros: facilitan el mantenimiento y las pruebas.
  • El siguiente paso natural es el backend: Node.js, APIs y bases de datos.

🧠 Comprueba lo aprendido

Elige una respuesta en cada pregunta. Verás al instante si acertaste y por qué.

¿Por qué el total del carrito no se guarda en estado?

Los valores derivados se calculan en cada dibujo a partir de la fuente de verdad.

Al «restar» un producto con cantidad 1, ¿qué debe pasar?

El reductor descarta con filter las líneas cuya cantidad llega a 0.

¿Qué debe devolver siempre un caso del reductor?

Nunca se muta el estado anterior: se crean copias.

¿Cómo se recupera el carrito guardado al iniciar?

La función inicial se ejecuta solo una vez al montar.

¿Qué te permite el hook useCarrito()?

Encapsula useContext(CarritoContext) en un solo lugar.
