Más hooks: useRef, useReducer y hooks propios

  • ⏱ 55 minutos
  • 📶 Nivel: principiante
  • 🧩 Incluye ejercicio

💡 🎯 Al terminar esta lección podrás…

  • Acceder al DOM y guardar valores mutables con useRef.
  • Organizar estados complejos con useReducer.
  • Saber cuándo (y cuándo no) memorizar.
  • Crear y reutilizar hooks personalizados.

1.useRef: una referencia que no provoca dibujos

useRef devuelve un objeto que se conserva entre dibujos y cuya propiedad .current puedes leer y cambiar sin que React vuelva a dibujar. Tiene dos usos principales:

UsoEjemplo
Acceder a un elemento del DOMEnfocar un campo, hacer scroll, medir un tamaño, reproducir un video
Guardar un valor mutable que no se muestraEl id de un temporizador, el valor anterior de algo, un contador interno

⚠️ Importante · Estado frente a referencia

Si el valor se muestra en pantalla, debe ser estado. Si solo lo necesitas «recordar» sin dibujarlo, usa una referencia. No leas ni escribas ref.current mientras dibujas (en el cuerpo del componente): hazlo en eventos y efectos.

2.useReducer: estado con muchas acciones

Cuando un estado tiene muchas formas de cambiar (agregar, quitar, editar, vaciar…), repartir setX por todo el componente se desordena. useReducer concentra toda la lógica en una sola función, el reductor, que recibe el estado actual y una acción y devuelve el estado nuevo.

3.useMemo y useCallback: optimizar con cabeza

React es rápido por defecto. Solo cuando midas un problema de rendimiento te servirán estas dos herramientas, que recuerdan un resultado entre dibujos:

HookRecuerda…Se recalcula cuando…
useMemo(() => cálculo, [deps])El resultado de un cálculo costosocambia alguna dependencia
useCallback(fn, [deps])La función misma (misma referencia)cambia alguna dependencia
⚛️ useMemo: no repetir un cálculo pesado
Consola

⚠️ Importante · No los uses «por si acaso»

Memorizar tiene un costo (memoria y código más difícil de leer). Empieza sin ellos, mide con las herramientas de desarrollo y úsalos donde de verdad haya lentitud. useCallback solo aporta algo cuando pasas la función a un componente envuelto en memo o a las dependencias de un efecto.

4.Hooks personalizados: reutilizar lógica

Un hook personalizado es una función cuyo nombre empieza por use y que usa otros hooks dentro. Sirve para extraer lógica con estado y reutilizarla en varios componentes, igual que un componente reutiliza JSX.

⚛️ useToggle y useContador
Consola

📌 Nota · Se comparte la lógica, no el estado

Cada vez que usas un hook personalizado, cada componente obtiene su propio estado. Los dos <Votos /> tienen contadores separados aunque usen el mismo hook.

Un clásico: useLocalStorage
function useLocalStorage(clave, inicial) {
  const [valor, setValor] = useState(() => {
    const guardado = localStorage.getItem(clave);
    return guardado !== null ? JSON.parse(guardado) : inicial;
  });

  useEffect(() => {
    localStorage.setItem(clave, JSON.stringify(valor));
  }, [clave, valor]);

  return [valor, setValor];
}

// Se usa igual que useState, pero persiste
const [nombre, setNombre] = useLocalStorage("nombre", "");

5.Las reglas de los hooks

  • Solo en el nivel superior: no los llames dentro de if, bucles ni funciones anidadas.
  • Solo en componentes o en otros hooks: no en funciones normales de JavaScript.
  • Los hooks personalizados empiezan por use: así las herramientas reconocen que son hooks y vigilan las reglas.

💡 Consejo · Instala el linter

Los proyectos de Vite traen eslint-plugin-react-hooks, que te avisa si rompes estas reglas o si olvidas una dependencia. Es de las ayudas más valiosas al aprender.

6.Errores frecuentes

  • Usar ref.current para algo que se muestra: la pantalla no se actualizará; usa estado.
  • Leer ref.current mientras dibujas: puede estar null en el primer dibujo.
  • Mutar el estado dentro del reductor: debe devolver siempre un objeto nuevo.
  • Olvidar el default del reductor: una acción mal escrita pasa desapercibida.
  • Usar useMemo por todas partes: añade complejidad sin beneficio medido.
  • Dependencias incompletas en useMemo y useCallback: devuelven valores viejos.
  • Un hook personalizado sin use al inicio: React no puede comprobar las reglas.

📒 Apuntes para llevar

  • useRef guarda un valor mutable que no redibuja y da acceso a elementos del DOM (ref={campo} → campo.current).
  • Si se muestra en pantalla, es estado; si solo se recuerda, es ref.
  • useReducer(reductor, inicial) centraliza los cambios de un estado complejo con acciones (dispatch({ tipo })).
  • El reductor es una función pura: (estado, acción) → estado nuevo.
  • useMemo recuerda un resultado; useCallback recuerda una función. Úsalos solo si mides un problema.
  • Un hook personalizado (useAlgo) extrae lógica con estado para reutilizarla.
  • Reglas de los hooks: nivel superior y solo en componentes u otros hooks.
